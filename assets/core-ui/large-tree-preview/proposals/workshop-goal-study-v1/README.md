# 目標から組む経路の局所試作

案4の圧縮延長を中止し、欲しい目標と道中の恩恵から接続を組み直した別案。全体645点の新配置は未完成で、このファイルを実ゲーム完成として扱わない。

- 原版と案1〜4は変更していない。
- 原645個のデータをHTML内に完全一致で保持。表示は戦士の109点・9領域・121接続。
- 表示したノードの効果・コスト・入力条件は、座標以外すべて原データと同一。
- 術式を強制取得させず、技能や装備MODを新規に付与しない。
- 防具の自由混合・artifactシリーズ・任意の魔術MODとは別に、既に持つ力への投資を比べる。

## 案4で反復を生んだ制約

各領域を同じ二股に変換し、共通環から同じ角度間隔・同じ距離で伸ばした。Keyも同じ形の末端へ置いたため、目標や隣接する恩恵より配置規則が優先された。左右の釣合いを内部すべての完全鏡像へ広げたことも、異なる目的の領域を同じ形にする原因になった。

今回は完全鏡像・共通外周環・共通セルを局所設計の必須条件から外した。装甲の広い二入口、生命の異なる二経路、回復の小さな寄り道、耐性の二つのNotable、吸収の大きな回り道、障壁の目標枝、物理の短い目標と追加の末端、手数の二段目標、資源の横断経路を個別に設計した。無関係な点への線の侵入は禁止し、ランダムな配置にはしていない。

## 同じ48ptで比較する配分

固定条件は現行の戦士support/plain/standard、雄叫びによる障壁入力、所有済みの吸収MOD。魔術入力はない。Key01とKey05の説明・代償は原案のまま。

上の数値は仮のパッシブ合計。装備の吸収MODそのものは合計へ足していない。Key01の最大HP15%乗算減、Key05の回避喪失・ヒット軽減、装備基礎値との最終合成も未実装。優劣や実戦balanceの検証結果ではない。配分を最後まで埋める最適化例でもない。

クリックで目標までの候補経路と必要な新規ポイントを表示する。緑が候補、金が取得経路。配分ボタンは表示した道を既存の入力条件・予算で確認してから取得する。ダブルクリックでは隣接点を1つ取得・解除できる。

狭い画面では点の可読寸法を維持するため広域表示が横へ続く。ドラッグ・ピンチと「起点へ」で移動できる。全109点が狭い画面に同時表示される仕様ではない。

## 実物参照

[GGG公式公開データ](https://github.com/grindinggear/skilltree-export/blob/master/data.json)を取得し、実ノードの座標と接続からDuelist→Iron Reflexes・Vaal Pact・Unwavering Stanceを描画して確認した。Keyは任意の袋路になり、周辺の目標と経路は大きさ・枝数・接続が異なる。ProjectSへPoEのノードやMasteryを移植していない。

[GGGの3.16公式説明](https://www.pathofexile.com/forum/view-thread/3186390)でも、領域の識別性、適切なKey位置、経路上の生命投資の偏りなどが設計課題として説明されている。今回の目的別構造は、その資料と実接続を見て行ったProjectS側の設計判断。

本人指定の[Rinaorc動画](https://x.com/Rinaorc/status/2105607235602899422?s=20)は投稿が返した原MP4を取得し、実再生の後、0.4・3.4・6.8・9.8・12.5秒を確認した。全体から目標へズームし、狙った点への経路と取得前の費用を読める表示を今回の候補経路に反映。動画のMinecraft内の描画方式・通信方式は外観だけで断定していない。原動画と参照用フレームは非公開の作業資料に留めた。

## 検証

- 実ブラウザで3配分の取得、独立Python計算との費用・合計値一致、保存・復元を確認。
- 吸収MOD入力を外すと配分をリセットして通知し、Key01とその配分を拒否する。拒否された配分ボタンは現在の配分・通路の恩恵を変更しない。
- 目標までの候補費用と実配分費用が一致。クリック取得・解除、ドラッグ、ホイール、モバイルのピンチを確認。
- 全線の自己交差・共通端点の別位置での交差を含めて線交差0・線重なり0。
- 全109点と全線に対し、選択枠・最大線幅を含めた最小点線間隔7.65px、最小点同士間隔4.36px。画面ラベルと線の重なり0。
- 外部画像・外部フォント・外部APIへの実行時リクエストなし。compile・nativeの重いrender・installは行っていない。

再生成は `scripts/build-skill-tree-goal-study.py`。専用QAブラウザ起動後の確認は `scripts/verify-skill-tree-goal-study.cjs`。全線確認は `scripts/audit-skill-tree-goal-study.py`。比較画像は `scripts/make-skill-tree-goal-comparison.py`。破綻した時は `candidate-region.json`、`browser-verification.json`、`complete-wire-verification.json` から確認する。

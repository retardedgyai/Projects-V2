# 目標の異なる育成圏をつなぐ局所試作 V2

再開指示の後、保存済みのV1（e051c29a）を読み、その続きから作成した別版。原版・案1〜4・V1を上書きせず、全645個の原効果を完全一致で収録する。新しく配置した部分は153点・13領域・173接続。全645点の新配置、native UIへの反映、実戦効果は未完成。

## 何を変えたか

範囲の二つのNotableと末端を持つ大きな扇、単発集中の小さな任意分岐、裂傷の長い分岐と短い分岐、最後の小さなY型を追加。物理への投資から入るか、資源や手数を拾って回るかを選べるようにつないだ。同じセル・半径・角度へ載せる生成規則は使っていない。

回復圏では、再生の恩恵へ到達するために純回復の入力が必要になっていた。現在使える再生へ一般の道から到達する入口を追加し、回復専用の枝を別に残した。効果・コスト・入力条件を緩和した修正ではない。

| 配分例 | 使用pt | 残りpt | 狙う目標 |
|---|---:|---:|---|
| Keyに先に届く | 29 | 19 | 不動の核・守りの循環 |
| 生命・耐性・吸収を拾う | 42 | 6 | 同じ2Keyと道中のNotable |
| 一撃・手数・資源 | 24 | 24 | 物理・攻撃速度・資源のNotable |
| 近接の広さ | 24 | 24 | 範囲の二つのNotable・余波の契約 |
| 連撃を一撃へ | 16 | 32 | 物理のNotable・単発集中 |

5例は同じ48pt、現在の戦士support/plain/standardと所有済み吸収MODの条件。予算を埋める最適化例や実戦の強さの順位ではない。旧3例の費用・集計・配分はV1と同じ。Key06の「近接技能の範囲半径50%乗算増／直接ヒット25%乗算減」、Key08の「複数回技能を一撃へ集約／手数・命中機会を失う」は原案のまま。数値の最終合成や技能の実動作には反映していない。

## 現行入力と、まだ使えない入力

`CoreSkillCatalog.kt`の現在の状態enumはNONE・SLOW・MARK・EXPOSE・POISON。現行の技能・装備catalogから出血付与は確認できず、元データの60プロフィールにもBLEED_SOURCEはない。Key03のBLEED_SOURCE条件を保持し、取得不可として表示する。出血Smallは入力不足、物理との混合Notableでは物理側のみ有効。新しい出血技能・装備MOD・仮の所有入力を勝手に追加していない。

近接と複数回技能の入力は、現在の戦士の装備技能にある。魔術入力を要求せず、今の技能をどの方向へ育てるかを比較する。防具シリーズ・魔術MOD・技能の新規習得とは別の役割。

## 実物参照と表示

[GGG公式の公開ツリーデータ](https://github.com/grindinggear/skilltree-export/blob/master/data.json)から実接続と座標を読み、任意のKeyと周辺の異なる育成圏を確認して設計した。[本人指定のMinecraft動画](https://x.com/Rinaorc/status/2105607235602899422?s=20)も原MP4を実再生し、0.4・3.4・6.8・9.8・12.5秒を確認済み。目標までの候補経路・取得前の費用を表示する点を参照した。動画の技術方式は未断定。

クリックで狙った目標までの現在使える候補経路と新規費用を表示し、配分前に確認できる。緑が候補、金が取得経路。入力を外した時は配分をリセットして通知する。取得不可の配分は、現在の配分・通路の恩恵を変更しない。狭い画面ではドラッグ・ピンチ・「起点へ」で探索する。

## 検証

- 原645データのHTML内完全一致と、表示ノードの座標以外の全フィールド一致。
- 5配分の実DOM操作・費用・恩恵合計を独立Python結果と比較。
- 全線の自己交差・共通端点を離れた交差を含め、線交差0・線重なり0。
- 全153点の枠・最大線幅を含め、最小点線間隔4.49px、最小点同士間隔4.36px。文字と線の重なり0。
- 現在使える全非Keyノードへ、Keyを通らず有効な入力だけで到達できる。
- 出血入力なしのKey03を拒否し、配分を変更しない。
- 保存・復元、クリック配分・解除、ドラッグ、ホイール、モバイルのピンチを確認。
- native compile・Minecraftの重いrender・install・main変更・pushなし。

再生成は `scripts/extend-skill-tree-goal-study-v2.py`。描画と操作の検証は `scripts/verify-skill-tree-goal-study-v2.cjs`。線の検証は `scripts/audit-skill-tree-goal-study-v2.py`。元のV1生成器を読み込むが、書き込み先とテンプレートをV2へ置き換えてから評価し、V1を再生成しない。

## 実装へ進めるときの条件

1. 実サイズのピクセル輪郭・限られた色面を確定する。高解像度画像をそのまま貼って完了にしない。
2. 刃と薄い装飾の絵を薄い面で保ち、握りや宝石にのみ必要な厚みを付ける。
3. UVと厚みが正面の絵を壊さないか、側面と背面も確認する。
4. 一人称/三人称/GUIの実モデルを比較する。美化したコンセプト画像だけで合格にしない。
5. 全職への展開でも同じピクセル密度と質感を保つ。既存の箱組み共通素材方式へ戻さない。

## テクスチャの輪郭に沿った薄型モデルの試作

`sword-mesh-v01.json` → `scripts/build_texture_first_sword.py` →
`.tools/texture-first-native/assets/projects/` の native item/model/texture。
出力は通常RPと分離しており、プレイヤーの武器は変えない。

刃は厚さ0.12、鍔は0.5、握りは0.85（1/16ブロック単位）。
正面/背面は原稿のUVを保つ面、側面はアルファ輪郭に沿った線分だけ。
不透明ピクセルを1個ずつ立方体にする方式ではない。原稿はバイト単位で同一コピーする。
透明な穴も側面生成で埋めない。26.2の `ItemModelGenerator.NORTH_FACE_UVS` を
ローカルclient jarで確認し、north面の反転Uを合わせた。

再生成と検証（repo root、Pillow/numpyが入ったPython）:

```powershell
python scripts/build_texture_first_sword.py
python scripts/test_texture_first_sword.py
```

出力 `views.png` は保存されたJSON/PNGを読む正面・斜め・側面・背面の確認画像。
Minecraft画面でも完成品質の証明でもない。共通プレビューは、片面のみを持つ要素、
native面のUV方向、`shade=false` を扱えるように修正した。

初回は構造検証6件成功、側面542面+表裏用3要素=545要素、モデルJSON約100KB。
この数は完成品の推奨値ではない。原稿の微小な輪郭ノイズも拾っているため、
本番用の低解像度原画を確定して輪郭を整理する必要がある。
側面抽出のalpha閾値128はこの試作用。native描画の閾値と同一と保証しない。
宝石の独立した絵、裏面固有の作画、装備時位置合わせとゲーム内動作が残る。

## 宝石の独立面と構え/復帰の試作

元原稿の宝石領域を、設定ファイルの範囲・種点・赤系色の条件からジオメトリ用に選択。
画像は編集せず、同じ元PNGのUVを参照する。前後面も輪郭内の連続した長方形に分け、
ダイヤ形の外側に四角い板や別の金属柄を足さない。
宝石の厚さは0.4。構え6ポーズで前へ0.3、放出6ポーズで前へ0.5から静止位置へ戻る。
最後のポーズは静止モデルと同一。刃・鍔・握り・UVは動かさない。

`jewel-action.gif` は出力された12個のJSONと実PNGを読む確認アニメーション。
参考動画の武器変形を再現したと主張するものではなく、独立面を動かす経路の試作。
宝石の裏面と下に残る台座の絵は元の正面原稿を再利用しており、本番作画は未完了。
現在781要素（宝石236）、JSON約148KB。微細な輪郭由来の面が多く、軽量化も残る。

構造検証9件成功。新規検証は、輪郭内の面の欠け/重複、偽の透明背景の拒否、
全12ポーズでの元画像/非可動部分の保持、静止位置への完全復帰。

### nativeアイテムからアクションモデルを選択

当初のitem定義は静止モデルだけを参照し、12ポーズは生成されても選択できなかった。
`build_texture_first_sword.py` の `item_definition()` で、既存サーバーと同じ
CustomModelData float0の12〜17を構え、18〜23を放出へ接続した。
0〜11は静止（この原稿には待機ループ未制作）。未設定/負値/24以上も静止へ戻す。

一人称/三人称の左右の手持ちだけがこの分岐を使う。GUI・額縁・ドロップ・頭などは
常に静止モデル。`hand_animation_on_swap=false` は、ポーズ切替を武器の持ち替えとして
毎回振り下ろさないためのnative設定であり、クライアント改造ではない。

テスト10件成功。追加検査は実際に書き出したitem定義を読み、全12ポーズ・境界値・
非手持ちコンテキストの参照先とモデルファイルの存在を確認する。
これはJSON分岐の検証で、Minecraftでの見え方・実際のスキル発動との接続確認ではない。
出力は引き続き `.tools/texture-first-native` のみ。通常RP登録と装備差し替えはしていない。
問題が出たら同ディレクトリのitem定義→float0→対応するmodel JSONの順で確認する。

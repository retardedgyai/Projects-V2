## Dungeons もとの技の作り方（手順）

2026-11-02 に突風・氷槍の列・流星と落雷で決まった作り方。手本の版は `../canon/mage-harness-trio.md`・`../canon/lightning-v6.md`・`../canon/tornado-v7.md`（どれも正典候補）、
火炎弾は `../canon/fire-bolt-v21.md`、氷は `../canon/frost-nova-v12.md`。

1. **技の中身を読む。** `server-minestom/.../coreloop/CoreSkillCatalog.kt` の説明・範囲（radius）・発生（startup、tick）・元素。何が起きる技かを一言にする。
2. **Dungeons の近い技を見る。** `~/ProjectS/refs/dungeons/INDEX.md` と `notes/` で探し、`sheets/` のコマを見る。寄せる先を一言書く（`../README.md` の作法2）。
3. **Dungeons から借りるのは4つだけ。**
   - 流れ：印 → 白い1コマ → 本体 → ほどける。
   - 部品：体を光らせる・輪・細い線・角ばった煙・四角い粒・ドット絵の板。
   - 色：1技1色＋白。**正典候補の色が先**：火は橙・黄（火炎弾 第21版）、氷は白い縁と紫の斑点（霜の波紋 第12版）、雷は水色＋白（落雷 6版目）、**風は薄い緑＋白**（突風 3版目。Dungeons の README の「風は水色」より先）。新しい元素の色は藍に聞く。
   - 時間：一番強い所（白い1コマから本体が立ち上がるまで）は 2〜6 tick。置いて続く技は、そのあと強さを落として続け、当たりのたびに敵を2tick白く光らせる。
   - 技の副効果（燃えた敵・凍った敵の火や氷を広げる、など）は1版目では描かない。1技1色を崩すので、入れるかは藍に聞く。
4. **描き方は全部 16 ドット。** 1ブロック16ドットの手描きの板、1/16 のドット、ブロックの物。
   板は回してよいが、伸び縮みさせない（1ドットはいつも 1/16 ブロック）。大きさを変えたい時は、その大きさの絵を別に描く。
   なめらかな光の部品（光る輪・帯・半透明の形・太さのある光の線）は使わない。光は後処理のにじみと点光源だけ。
5. **起きている物を入れる。** 光と色だけで作らない。例：風の筆と舞う葉、積み木の氷、燃える岩と飛ぶ地面のブロック、雷雲と焦げ。
6. **一人称に合わせる。**
   - 手前2ブロックより近くに物を立てない。
   - 半球で範囲を見せない。プレイヤーのまわりに半球を出さない。
   - 列で並ぶ物は、まっすぐ奥へ並べると1つの束に重なるので、扇に広げる。
   - 空から来る物は、視線に入る高さに置く（必要なら見本のカメラを少し上げる）。
7. **地面に属性を残さない。** 状態は敵だけに付ける（`../ng.md`「なんで魔法使ったら地面に属性がのこるの？」）。焦げや飛んだブロックのように、物が2秒ほどで欠けて消えるのはよい。
8. **同じ見本ページに足す。** `~/ProjectS/refs/mage-vfx/preview/`。新しい技は `src_mage2.js` と同じ書き方で、**技ごとに新しいファイル** `src_<名前>.js` を作る（手本：`src_tornado.js`）。
   - 使える部品：`kitBegin`/`kitEnd`、`tint`、`pixRing`、`puff`、`streak`、`crawl`（`src_thunder.js`）、`board`/`pix`/`bill`、`light`。火炎弾の絵 `LICK`・`TALL`・`BURST`（`src_fire.js`）、氷の `iceM`・`flakeTex`（`src_frost.js`）。
   - 技の登録は5か所：`build.py`（組む一覧の `src_mage2.js` の後）、`src_thunder.js` の `DKIT` の一覧（`kitBegin` が使う線や輪の部品がここで作られる）、`src_head.html`（技の節・敵の置き場所 `placeMob`・`setCam` のカメラの傾き）、`src_tail.html`（呼び出し）。2版目からは、前の版を `src_<名前>_vN.js` に残す。
   - 名前がぶつからないよう、技の中の物は `O.<技の名前>…` のように技ごとの名前にする（`O.rings`・`O.lines` などは共通の部品が使っている）。
   - 撮るのは**一人称（cam=0）・夜（scene=night）**。`python3 build.py` で組み、`python3 sheet.py <出力> <技> 0 night <tick…>` で並べて撮る。1枚は `shot.sh <出力> "t=<tick>&cam=0&only=<技>&scene=night"`。どちらも1本ずつしか動かない（PC が重くなるので並べて走らせない）。
   - カメラの傾きは、技の物が画面に入る最小に（地面の技は下向き -0.1〜-0.24、空から来る技は上向き 0.02〜0.06）。
   - 夜はブロックや敵が暗い。運ばれるブロックなど見せたい物の近くには `light()` で技の色の光を置く。
   - ページの見出し（`src_head.html` の `<h2>` と説明）は、出した版の中身に合わせて書き直す。
9. **撮って拡大して、荒い所を詰めてから出す。** 前の版と並べたページ（Artifact）で、コマと一緒に出す。1コマは1tick。
   - 大きい物（2ブロックを超える）ほど、線は1〜2ドットに細くして本数を増やす。太い線を少し並べると、16ドットでも粗く見える（竜巻 1版目「ドットが荒すぎる…大きさの割には」）。
   - 回る・流れる動きは、絵を8枚以上にして毎tick進める。乱数で位置を跳ねさせない（同じく「アニメーションも」荒い）。
   - 動きを見せる GIF は1tickごとに撮る（2tickおきだと実際より粗く見える）。
   - 立っている物は、軸を左右と前後の両方へなめらかにうねらせ、tick の間も画面のフレームの時間で動かす（竜巻 3版目「うねり方とか動き方は前より竜巻してる」）。まわりの物（葉・ブロック・筆）も同じうねりに乗せる。
   - 消えるときは、その場でドットを欠けさせて消さない（映像が消えるようでホログラムっぽい）。物がほどけて、勢いのままドットが散るように消す（竜巻 5版目「スンって消えるんじゃなくて散るように消えよう」）。散る物はその元素らしく動かす：風は落とさず、回る勢いのまま外へ流して少し浮かせ、動く向きに伸びた短い筋にする（竜巻 6版目で重さで落としたら「砂が落ちてるみたい…もっと風らしく散ってほしい」）。
   - **大きく続く物（竜巻など）は、16ドットの模様をシェーダーで動かす**（藍「シェーダーで…全体的にかな？」、竜巻 7版目で及第点）。模様は表面の 1/16 ブロックの格子に合わせ、1ドット単位でフレームの時間に合わせて動かす。手本は `../canon/tornado-v7.md`。
   - シェーダーで面に16ドットの模様を流す作り（竜巻 3版目）は良い所がある：「ドットがきれいに動いてて、ホログラムっぽくもあるんだけどちゃんと陰影で再現できてるのはすごく良い」「周りにブロックが巻き込まれてるのも芸が細かくて好き」（2026-11-03）。輪郭ほど濃くして立体に見せる、物を巻き込む、を残す。ホログラムっぽさ（全面に均一に透ける光の線）は減らす。
10. **藍の言葉を `../log.md` に一行。** OK なら `../canon/` に正典候補として1ファイル。

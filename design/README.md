# design/ — 見た目を作るときの入口

見た目（エフェクト・UI・装備・ボス・建築）を作る前に、ここを読む。
2026-10-28 に火炎弾だけで21版、藍への判断が20回以上、ほぼ却下という一日があった。
原因は「AI が手本なしに推測で作り、藍が曖昧に却下する」の連鎖。うまくいったのは、
藍が画像で手本を指した時と、ゲームの中で「一瞬光る」「氷が残る」と具体的に言えた時だけ。
ここは、その2つを先に起こすための文書と作法。コードや道具は作らない。

## 作法（5つ）

1. **読んでから作る。** この README、該当する棚（`shelves/`）、`ng.md` を読む。
2. **寄せる先を一言書く。** 「どの手本の、どこに寄せるか」を書いてから作る。
   寄せる手本がなければ、作らずに藍へ「手本は？」と一つだけ聞く。
3. **1版目は正典と同じ媒体と作りで出す。** `canon/` と同じ見本の道具・同じ部品の作りで出す。
   見本の道具や媒体を替えない（2D の板で出した霜の波紋は「プレビューからなにからなにまで違う」）。
4. **最終の OK・NG はゲームの中で決める。** 見本（同じ媒体）への OK は「正典候補」まで。ゲームの中で OK が出たら「正典」。藍の言葉を `log.md` に一行残す。
5. **曖昧な却下には聞き返す。** 「なんか違う」が来たら次の版を作らず、どこが違うかを一つだけ聞く。

## 中身

| 場所 | 何か |
|---|---|
| `canon/` | 正典と正典候補。ゲームの中で藍が OK した物が正典、見本への OK だけの物が正典候補。1件1ファイル。新しい見た目はここに寄せる |
| `shelves/` | 分野ごとの手本棚。`README.md` に行の形、`vfx.md` にエフェクトの候補 |
| `ng.md` | ダメな例。藍の言葉のままと、その理由 |
| `rules/` | 共通の決まりへの案内（既存文書を指すだけ。複製しない） |
| `log.md` | 判断の記録。日付・何を見て・OK か NG か・理由一行 |

## 書き足すとき

- 藍が OK を出してゲームに入ったら `canon/` に1ファイル。藍の言葉と決め手を必ず書く。
- 藍が NG を出したら `ng.md` に藍の言葉のまま。理由は藍の言葉から読めることだけ書き、作り話で埋めない。
- 棚の「何が良いか」は藍の言葉がある物だけ書く。ない物は「藍が書く」のまま置く。
- 動画・画像そのものは `~/ProjectS/refs/` に置いたまま、場所を指す。repo に入れない。

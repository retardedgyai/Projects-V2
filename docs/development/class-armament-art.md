# 全職武装アート：制作記録（未完成）

## 最優先の制作基準（2026-09-08 更新）

ユーザー指定の [The Dark Sister](https://x.com/MatE312001/status/2096478906299699459) を、
今後の武装すべての質感基準とする。下記の既存実装は技術的な初回実装の記録であり、
その箱組み造形や共通素材アトラスを、承認されたアートの方向性として引き継がない。

- **テクスチャに合わせて形を作る。** 刃・薄い鍔の飾りは、絵の輪郭と陰影が主役。
- 完全2D化は要求されていない。握り・宝石・重なりなど、必要な箇所だけ厚みを付ける。
- 単に直方体を積み重ねて武器を作る手法は禁止。部品数を増やして品質の代用にしない。
- 大きい色の塊、段階的な陰影、細く鋭い輪郭、暗い本体と明るい刃の対比を保つ。
- 微細な金属ノイズ、滑らかなグラデーション、高解像度の光沢で精密感を足さない。
- 色やモチーフを変更しても、ピクセルの粒度・陰影・輪郭・厚みの質感を逸脱させない。
- 正面だけでなく、斜め・背面・側面・実際の手持ちサイズで比較する。
- 構造テスト成功やモデル数の充足は、この質感の達成を意味しない。

公開動画では薄く見える刃と立体感のある柄を観察したが、元のメッシュ/UV構成は未取得。
「元モデルも完全な2D面」と断定しない。完全一致は現状未達であり、保証済みと報告しない。

未commitだった箱組みT3/T4追加案は生成経路から外し、ローカルの
`.tools/rejected-block-armaments/class_armament_hero.py` に保管した。既存の戦闘/アニメーション機能は戻さない。
既存RPは引き続き仮アートであり、今回の更新で全武装が置き換わったわけではない。

新しい [テクスチャ先行原稿と生成記録](../../assets/class-armaments/texture-first/README.md) は
制作途中の資料。ゲーム用テクスチャとしては未採用。ここから輪郭に沿う薄い面と必要な厚みを設計する。

## 受け入れ条件を縮小しない

全7職の武器・防具、武器のアニメーション、指定リファレンスと同等の造形・作画品質が対象。
SamusDev の全動画確認と、可能ならスキル表現の向上も残る。
28個のモデルが存在することや構造テスト成功だけでは、品質条件の達成にはならない。

ユーザーの直近の修正：高解像度な質感は不要。輪郭・厚み・装飾は凝り、表面は粗く明確なピクセルで描く。
生成した1692×929の設計画・1254×1254の素材画は採用しない。RPに入れず、貼り付けない。

### 適用経路

`class_armament_geometry.py` → `build_core_weapon_assets.py` → namespaced RP →
`CoreLoopItems.gear`（RP成功時のみ） → `CoreArmamentPresentation.tick` → モデルフレーム選択。

通常の弓も専用モデル化。STAFFという装備種を変えず、星織り師だけ星環杖のモデルを選ぶ。

共有クラス基盤、ダメージ判定、保存形式、client-fabric、承認済みUI/fontは変更しない。

## Vanilla 26.2で確認した制約

ローカルの `minecraft-client.jar` を `javap -c -p` で確認：

- `LocalTime.UPDATE_INTERVAL_MS` は1秒。小数秒のパターンを指定しても10fpsにはならない。
- `ItemInHandRenderer.shouldInstantlyReplaceVisibleItem` は、対象の `hand_animation_on_swap=false` の場合、更新アイテムを即時交換する。
- `ItemModelResolver` → `ClientItem.Properties.handAnimationOnSwap` がその参照経路。
- 現状の実装は標準 `custom_model_data` のfloat0で12コマを選び、2tick間隔で手に持っている装備のみ更新する。
- GUI/fixed/groundは静止。サーバーが把握するコンテナを開いている間は更新しない。
- フレーム更新に独立タイマーや追従エンティティを増やさない。

これはクライアント改造ではないが、完全なボーンアニメーションでもない。
世界に表示した回転プレビューを「装備中のアニメーション実装」と誤認しない。

### 頭と胴の描画経路を分ける根拠

Vanilla 26.2のローカルclient JARで確認：

- `HumanoidArmorLayer.shouldRender` はEquippableのassetIdが存在し、装備slotが一致するとtrue。
- `LivingEntityRenderer` は頭で上の条件を満たすとCustomHeadLayerのitemを使わない。
- したがって兜のみ `Equippable.assetId=null` とし、独自item modelを頭に表示する。
- `CustomHeadLayer.translateToHead` はY=-0.25の移動、Y=180°回転、(0.625,-0.625,-0.625)スケール。
  モデルのhead scale=1.6で縮尺を相殺し、model y=3.5〜12.5を頭周囲の薄い殻にする。
- 胴/脚/足はassetIdに`projects:armor/<job>_t<tier>`を指定し、native装備textureを利用する。
  脚はhumanoid_leggings、その他はhumanoid。歩行追従を独自entity更新で代用しない。

`verify_class_armor_assets.py` は56テクスチャの実寸/不透明度/原稿一致、112モデルの境界とindex、
28組の外観差を確認する。`CoreArmorPresentationTest` は全112投影、装備slot/既存成分保持、
パック無しへの退避、実際のrefreshを通した全職/全Tier/全slotの更新を検査する。

`preview_class_armor.py` は標準人型の近似と無地のマネキンに実際のtexture/modelを適用する。
`.tools/armor-review/all-sets.png` は確認用の生成物であり、Minecraftのスクリーンショットではない。
顔が無地なのは確認用マネキンのため。プレイヤーのスキンを書き換える処理はない。

## 成立済みアクションと連動する武器機構

`class_armament_actions.py` は全28武器に構え6ポーズ・放出/復帰6ポーズを追加。
待機336コマに追加の336ポーズ。既存の16px素材をそのまま使い、画像の解像度は上げない。

| 武器 | 構え/放出の意味 |
| --- | --- |
| 大剣 | 既存の溝に沿った光が伸び、放出後に収まる。刃全体の巨大化や追加の当たり判定はない |
| 杖 | 結晶籠が左右に開き、結晶が持ち上がる。放出後に籠を閉じる |
| 弓 | 握りを固定してリムがたわみ、矢をつがえて弦を引く。放出開始で矢が消え、リムが戻る |
| 短剣 | 刃の溝を反射が走る。汎用動作に毒の命中/付与を偽装しない |
| 戦槌 | 頭部の4枚の板が少し開いて核を露出し、放出後に閉じる |
| 聖典 | 構え中にページを背表紙の軸でめくり、祈りの印が持ち上がり、放出後に戻る |
| 星環杖 | 周囲の星片が中心へ寄って前へ出て、放出後に元の星配置へ戻る |

### 用途と接続

`CorePlayerCombat` の既存の成立済み演出 → `GreatswordVfx.playSkill` →
`CoreArmamentPresentation.skill` → 一時的なプレイヤー所有クリップ → 同じRPのフレーム選択。
共有Class runtime、Hit/Damage/Reward、Protocol、保存形式は変更しない。

- 構え時間は既存のスキルPREPAREの時間に合わせる。放出は最初のPULSE通知に接続し、12tickで復帰。
- 命中CONTACT、2回目以降の場のpulse、無効な座標は武器動作を再開させない。
- ブリンク、罠設置、ガードは武器放出の対象外。弓はARROW/RAINの射撃系だけに割り当てる。
- 近接通常攻撃は既存の `swingSound` 通知（実際の攻撃フレーム）で放出を開始する。
  構え時間を推測して入力だけから再生しない。
- 遠距離通常攻撃には既存の構え用VFX通知がないため、今回接続していない。
  共有runtimeへの新しい通知追加が必要なら、その境界変更は別途合意する。
- 新しいプレイヤー/追従エンティティ/独立タイマーは作らない。
  動作状態はプレイヤーのTransientタグで、装備やアカウントの保存データへ入れない。
- 途中の武器変更、マップ変更、パック解除、コンテナ表示、VFXキャンセルでクリップを破棄。
- GUI/fixed/groundは引き続き静止モデル。待機時の完全ItemStack更新コストの課題は残る。

検証はモデルの全ポーズ/UV/境界/索引に加え、全職の実際のactorのスキル0発動→放出→キャンセル、
拒否された発動、CONTACT/後続pulseの無視、武器切替/パック解除、2〜61tickの再生境界、
全28武器の336ポーズでのアイテム成分保持を対象にする。

確認用の `actions.gif` / `action-poses.png` は実モデルからの正投影出力。
Minecraftでの一人称の構え、サーバー転送中の滑らかさ、実機の見栄えは未検証。
モデルのポーズ一覧だけを「リファレンスと同じアニメーション品質」の証拠にはしない。

# 読めるメニュー v0

目的は、装飾を増やすことではなく「何を選んだか、何が起こるか、何が足りないか」をホバーせず把握できるようにすること。

## 基本操作

- 中央の文字付きボタンをクリックする。アイコンだけでなく、ボタンの横幅全体が同じ操作に対応する。
- 金色の下線は選択中。緑は実行、灰色は使用不可。選択しただけでは素材を消費しない。
- 左は対象と完成品・強化前後。右は必要素材・条件。素材数は **所持 / 必要**。赤と `!` は不足。
- 工房の「素材へ」から精製・補給へ進める。「元へ」で対象装備、制作レシピ、素材Tier、回数、触媒設定を復元する。復帰しても自動実行しない。
- 回数は `1` / `5` / `全`。全は素材と保管上限の両方から算出する最大回数（最大64回）。実際の完成個数は左に表示。
- 倉庫は所持品だけを表示する。大量在庫の一覧は「万」「万+」で省略し、選択した品の正確な個数は右に表示する。「全オーブ」は別の図鑑画面であり、未所持品も使用条件を調べられる。
- 装備の全MOD、ロール範囲、品質%、アイテムレベル、内部Tierは「装備詳細」と装備Tooltipに残す。Shift操作は不要。

## 適用範囲

手帳、遠征の地図一覧・調整、工房4タブ、素材調達、倉庫、補給、採取道具・育成、装備詳細、旧石交換、ボス試練、帰還確認、遊び方を同じ表示規則に統一する。

既存の大剣3Dモデル、戦闘エフェクト、HUD、装備Tooltipのテーマは維持。経済、ドロップ、強化確率、セーブ形式、クライアントのコードは変更しない。

## サーバーとリソースパック

バニラ26.2の6行チェストを使用し、全54操作スロットと下段36所持品スロットの位置は変更しない。サーバーから送るタイトルのフォントで背景、ラベル、左右パネルを描画する。UIラベルの下のスロットには既存の透明モデルを使用する。

メニューだけNoto Sans JP 600の10pxラスタを使用。文字は `projects:` 名前空間のPUAへ対応付ける。通常の日本語・英語フォントは上書きしない。フォント原本は開発用の `.tools/` に置き、配信するのは小さいアトラスとライセンスのみ。由来とハッシュは `assets/core-ui/fonts/README.md` に記載。

横幅は384 GUIピクセル。小さい画面や大きすぎるGUI倍率では左右が見切れるため、中央右上の `?` から表示調整の説明へ進める。サーバーにはクライアントのGUI倍率を取得する標準APIがないので、自動変更しない。

パックが成功応答するまでは通常アイコンと日本語Tooltipへフォールバックする。プレイヤーの操作をエージェントから実行しない。オフラインプレビューはフォント配置の検証であって、実ゲームのManual Smokeとは区別する。

## 実装の入口

`CoreLoopMenus` が読み取り専用の見積もりから画面と操作を作成 → `CoreMenuCanvas` が文字と配置を描画 → `CoreMenuInventory` が表示世代とクリックを管理 → `CoreMenuHost` 経由で既存のサーバー処理へ渡す。消費は既存ledgerが描画時revisionを再検証して確定する。

- 操作・導線：`CoreLoopMenus.kt`
- 常時表示・文字幅：`ui/CoreMenuCanvas.kt`
- 元の制作へ戻る状態：`ui/CoreForgeJourney.kt`
- 在庫・不足・保管上限の見積もり：`ui/CoreForgeSummary.kt`
- 窓の更新・非同期完了時のガード：`ui/CoreMenuInventory.kt`
- アセット再生成：`scripts/build_core_ui_assets.py`
- アセット検証：`scripts/verify_core_ui_assets.py`

メニュー更新時は現在のInventoryを再利用する。同じタイトルなら内容更新1回、動的パネルの内容が変わる場合はバニラ標準のOpenWindowと内容更新が必要。ESC、別の画面、切断後に以前の加工画面を勝手に開き直さない。パック読み込み完了時も現在の画面のTier・ページを維持する。

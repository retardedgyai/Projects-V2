# Polish05 工房UI・デザインレビュー

2026-09-30 / 比較元のコミット `0abe8eaa` / Playground

## 結論

**雰囲気と3列の構成は維持し、情報の優先順位を直すのがよい。**

暗い青緑、細い金の枠、選択行の左から薄くなる光、装備を中央で見せる構成は
ProjectSの個性になっている。全面的に別のデザインへ変える理由はない。
修正の優先順は「費用とリスクの読み取り → 選択した装備との一致 → 文字と余白」。
装飾を増やして品質を上げようとすると、既に多い小さな情報がさらに埋もれる。

比較用の [HTML案](../../assets/ui/polish05-design-review/index.html) を作成した。
ゲームへの実装変更やマージを求める提案ではなく、見た目と操作の具体案である。

## 確認したものと確認の限界

- 元の `ProjectS_UI_Polish05_Workbench.html` を1920×1080でブラウザ描画した。
- 現行の `Polish05Scene`、`CorePolish05ForgeFlow`、強化ルール、カーソルと回転処理を読んだ。
- 承認済みプレートのモデル・テクスチャ、出荷中の素材アイコンを確認し、案にも使用した。
- 今回はMinecraftを起動していない。元のHTMLに残る装備庫・精錬・銀貨費用を
  **現行ゲーム画面の仕様と混同していない**。
- カーソルの体感、最新のゲーム内フォントの輪郭、解像度変更時の見え方は
  このHTMLの動作だけでは評価できない。以下はソースと参照画像からのレビュー。

## 良い部分

1. **中央の展示が画面の目的を伝える。** 装備を見ながら強化する流れと合っている。
   承認済みプレートは面の明暗と金・布のアクセントが読み取れ、背景から分離する。
2. **金の光に役割がある。** 選択行、次の強化段階、実行ボタンを同じ色でつなぐ。
   素材の緑・赤も意味が一貫している。柔らかい光は保つ価値がある。
3. **左から右へ自然に進める。** 部位を選ぶ → 外観を確認 → 費用を確認、という順。
4. **NPCの工房一画面に絞った判断は良い。** 強化中に別の管理画面へ誘導しない。

### 破損の表現

現行 `breakOnFailurePercent` は **失敗した場合だけの破損率**。
「1回の試行に対する破損率」とは異なる。主画面で分母を明記すべき。
例えば +16 → +17 の素の成功率26%、失敗時の破損率8%なら、1回あたりの破損率は5.92%。
HTMLは「失敗した場合の破損率8.0%」と表現し、分母が違う数字を並べない。

実際に破損したときは、単なる「失敗・段階維持」より強い状態表示が必要。
`CorePolish05ForgeFlow` のreceiptは成功/失敗のBooleanで、結果説明でも破損を分けていない。
次の強化ができない理由と修理が必要なことを、結果で伝えるのを優先したい。

### 絵と仕組みの一致

プレート外観でも、現行ルールの防具強化費用は革・布・加工石材。
HTMLもそのルールを保持した。見た目から金属系の費用を期待しやすいため、
将来プレート・布・皮を正式なゲーム分類にする際は、レシピとの対応を別タスクで検討したい。
このレビューで能力値や経済ルールを変更する必要はない。

## デザイン案の意図

### 1. 左は「どの部位か」を読む場所

5部位のアイコン、名前、Tier、強化値を一定の位置へ。
緑のHPを各行へ繰り返さず、選択中の行を金色の縦線と薄い勾配で示す。
所持素材の表示と鍛造記録は残した。

### 2. 中央は外観を見る場所

既存の承認済みプレートを大きく展示。
新しい装飾や異なる画風の防具を足していない。
背景には既存の工房画像を暗く敷き、細い台座と少数の金色粒子で空間を作る。
装備の画素はぼかさない。タイトルのみ明朝、操作と費用は読みやすいゴシック。

### 3. 右は「何を払って何が変わるか」を読む場所

段階 → 性能の差分 → 成功率・失敗条件 → 全費用 → 確認、の順に揃える。
必要数を右端へ置き、所持→残りをその素材の直下へ。
足りないときは赤い光と「あとN個不足」を併用し、色だけに頼らない。
光は数字の周りで弱く広げ、文字とアイコンの輪郭を保つ。

「強化内容を確認」で確認画面へ進み、最後のボタンだけ
「素材を消費して強化」と明示する。結果表示は中央の独立した場所に出し、
右の次回予測と確定済みの結果を分離した。

## HTMLの扱い・操作

- [index.html](../../assets/ui/polish05-design-review/index.html) をブラウザで開く。
  ネットワーク接続、外部ライブラリ、インストールは不要。`art/` は隣に置く。
- 上の比較用設定で通常・不足・高段階・次回確定・上限・破損を切り替える。
  これはゲームUI外の確認用設定。
- 部位を選ぶ → 触媒を切り替える → 強化内容を確認 → 確定、の流れを試せる。
- 中央の防具をクリックするとマウスの左右移動で向きが変わり、もう一度クリックすると止まる。
  回転の説明文字は追加していない。武器は既存の静止絵で、回転を模擬していない。
- 防具は同じProjectSモデルを16方向から描画したPNG。ブラウザでの連続3Dレンダリングではなく、
  表示位置・余白・向きを比較するための見本。
- 装備名、能力値、Tier別の所持数は見本。確率・素材の種類と数量・天井は
  現行Catalog（熟練度0）に合わせた。成功/失敗は比較用設定で指定でき、100%時は成功になる。
  失敗見本は破損なしの結果。実際の抽選・保存・修理には接続していない。
- 小幅画面では縦に並べる。これはHTML閲覧用で、MinecraftにモバイルUIを追加する提案ではない。

### 本編へ反映する場合の順番

1. 文言修正、HPの意味、全費用、触媒上限、保証情報、破損結果の表示を先に直す。
2. 情報が減った分を装備一覧の文字・余白へ戻す。今の金色の光は調整を最小限にする。
3. 武器の画像参照と回転中のクリック処理を合わせる。
4. 実機の1920×1080で確認し、カーソルは別に体感テストする。

HTMLの文字描画やネイティブマウスの反応は、Vanillaの表示エンティティ方式へ
そのまま持ち込めない。現行入力の120Hzプローブ、60Hz本体更新と1tick補間には
通信と描画の制約がある。今回の案のネイティブカーソルを根拠に高速化できたとは判断しない。

## 確認結果

`assets/ui/polish05-design-review/verify.cjs` をPlaywright + Edgeで実行して成功。

- 5部位の選択、実モデルから生成した別方向の画像。
- 防具4素材・武器5素材の触媒費用と、確認画面での同じ一覧。
- 成功・失敗・鍛造中の無効化、他部位の強化値を変えないこと。
- 不足、高段階の条件付き破損率、天井保証、上限、破損状態。
- 確認画面のEscapeキャンセルとフォーカス復帰、工房の閉じる/開く。
- 1920×1080 / 1440×900 / 390×844で横方向のはみ出しなし、画像欠落なし、ブラウザエラーなし。
- 1920×1080では通常・全5素材時とも強化確認ボタンが画面内に収まる。
- 通常・全費用・確認画面・素材不足・小幅画面の描画画像を目視した。

実機テスト、Kotlinビルドは今回の変更対象外。
スクリーンショットは `.tools/polish05-design-review/`。破損描画等の問題は
まずHTML、次に `art/` の相対パスと `verify.cjs` の出力を確認する。

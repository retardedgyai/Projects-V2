# 開拓工房 UI v0

対象は Vanilla 26.2 のサーバー管理チェスト画面。クライアントMOD、共有フォント、シェーダー、HUD位置は変更しない。

## 操作の流れ

1. 左端の **強化 / 精製 / 制作 / MOD加工** を選ぶ。上の武器・防具の選択はタブを移動しても保持する。
2. 左のレシピをクリック。中央に対象と成果、右に必要数・所持数・不足数が出る。選択だけでは消費しない。
3. 精製・消耗品制作は下の **1回 / 5回 / 最大** を選ぶ。1回で回復薬2個など、回数と完成個数は区別する。最大は全入力素材・完成品保管上限・サーバーの64回上限で計算する。
4. 右下の実行ボタンで確定。保存成功後、同じ工房を最新残高・装備で表示する。右クリックに別の隠し数量操作はない。

装備Tierを上げた直後だけは強化タブへ戻す。T4到達でレシピ一覧が詰まった際、同じ実行位置への連打が別の消耗品制作へ変わらないため。

補給所の戦利品券交換も「素材を選択 → 1回 / 5回 / 最大 → 右下で確定」とし、選択クリックで即交換しない。倉庫は引き続き所持1以上だけを表示する。表示用アイテムは取り出せない。

右の費用素材をクリックすると、加工品はその素材Tierの精製レシピ、生素材は補給所、討伐証は該当Tierの地図台へ移る。加工品のショートカットでも対象の武器・防具は保持する。

## 強化

- 見積りは `CoreEnhancementCatalog.quote`、費用は `quote.recipe.costs` を正本とする。現在 → 成功後の強化分、成功率、基礎 / 熟練 / 触媒の内訳、失敗天井を表示する。
- 失敗で装備・強化値・MODは失われないが、素材は消費することを実行前に示す。
- 通常強化で既に成功確定なら、前回触媒を選んでいても今回は通常強化にする。最大+30でも実行しない。
- 熟練は0〜10。次ランクまでのXP、成功率加算を表示する。素材精製・制作のXPはレシピ回数に合わせて示す。
- 強化時に使用する素材Tierは強化段階に応じて決まり、費用見積りの内容をそのまま表示する。精製・消耗品制作の選択Tierとは独立している。

## MOD加工

目的は「すべて / レアリティ昇格 / MOD追加 / MOD引き直し / 数値・初期化」。主一覧は現在の装備へ使用可能で、所持1以上のオーブだけ。右上の本では未所持・条件不一致を含む全加工の説明を確認できる。

オーブを選択すると、中央に現在の装備と起こる変化、右に今回1個の消費と実際の所持数が出る。加工結果の乱数は先読みしない。外部のオーブ使用導線も `confirmCraft` からこの同じ工房の確認状態へ入る。条件不一致の加工は実行できない。

6MODの効果・ロール範囲・品質％・内部Tier・アイテムレベルは従来の装備ツールチップに残す。細かなMOD名称は装備上の本からも確認できる。

## 画面・画像

`CoreForgeLayout` が Vanilla 6行チェストの54スロットに各領域を割り当てる。専用背景は176×222 px。クリック判定は既存18 px格子のまま。プレイヤーインベントリ36枠の位置も変えない。

`projects:core_menu` の U+E201 が工房、U+E202 が未選択の工房。日本語は `minecraft:default` のまま表示する。パック未適用・拒否時は装飾なしの通常チェストに同一操作を用意する。

`assets/core-ui/forge-vignette-master.png` は2026-09-05に **OpenAI内蔵imagegen** で新規生成した金床・赤熱した大剣・ハンマーの原画。PixelLabは使用していない。原画1536×1024を技術的に48×32以内へ縮小し、MOD未選択時だけ中央の `(64,39,48,32)` に合成する。選択中の対象・成果・費用・実行に絵を敷かない。派生PNGとネイティブ枠は `scripts/build_core_ui_assets.py` で再生成できる。

方向性の参考は [Albion公式の制作ガイド](https://albiononline.com/news/guide-crafting) と [精製ガイド](https://albiononline.com/news/guide-refining) の採取→精製→制作、[Ravengard開発記事](https://hypixel.net/threads/dev-blog-13-a-look-at-ravengard.6023553/) の冒険的な工房・暗いパネル。UIの左右レイアウトは今回のタスク指定に沿って自前のチェスト座標へ設計したもので、外部UI画像そのものは同梱していない。

## 検証と手動確認

構造検証は `scripts/verify_core_ui_assets.py`。画像が費用・操作・プレイヤー所持品領域へはみ出していないこと、既存の日本語を置換しないこと、アイテム画像のatlas経路を検証する。

`CoreForgeLayoutTest` は枠の非重複、数量・上限、目的分類、使用可能オーブ一覧、装備選択、確定時の不要触媒抑止、パックなし日本語を確認する。乱数加工を繰り返した有効装備でも一覧が8枠内に収まることを確認する。

自動検証結果（2026-09-05、工房UI branch、強化domain 21bcd25を適用）: UI関連34件 + 強化12件 + 倉庫3件の計49テスト成功。パック構造検証は135 assets / 195 private glyphsで成功。統合先での強化素材Tierルール変更後の全体検証は別途行う。

ゲーム内の操作・最終的な見やすさはCreatorが確認する。まだ成功したと主張しない項目:

- 工房施設と手帳から同じ画面へ入れるか。武器・防具を選んで4タブ移動し、意図した対象が残るか。
- T1〜4の精製で数量と完成品が一致するか。素材不足・保管上限で実行不可になるか。
- 強化の成功・失敗後に残高、強化値、天井、熟練が更新されるか。天井到達時に触媒が外れるか。
- オーブ選択だけでは消費せず、確定時だけ変化するか。MOD数・種類・数値を装備のTooltipで読めるか。
- GUIスケール変更時の文字・アイコン・枠の見切れ、パック拒否時の通常チェスト操作。

最初に見るコードは `CoreLoopMenus.forge`、費用や成功率の不一致は `CoreEnhancementCatalog`。文字化けや背景ずれは `CoreUiComponents.inventoryTitle` と `core_menu.json`。素材残高の正否・保存競合は既存 `CoreAccountService` の責務。

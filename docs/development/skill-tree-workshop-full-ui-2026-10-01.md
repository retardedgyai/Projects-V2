# パッシブツリー：工房UI・全47領域の別案

局所10点の見本を全体要望の完成として扱わず、全645点／952接続／47領域を同じ画面で扱う別案。元の大盤面、Polish05原本、前の局所見本は残す。今回はネイティブゲーム実装ではなく、既存育成データを使う操作可能なUI資料。

## 育成の考え方

持っている武器・技・装備をどう伸ばすかを選ぶ。道中のSmallで違う恩恵を拾い、Notableで方向を強める。Keyは強みと代償のある任意のルール変更案。技の習得は別の仕組みで、この盤面から取得しない。防具の全職自由混合／artifact別series、任意の装備MOD変性・専用MODという魔術加工の方向は変更しない。

## 表示とデータ

- `workshop-full-v1/ProjectS_Passive_Workshop_Full.html` が全域版。全体、5起点、選んだ起点への移動、ドラッグ、ホイール、pinch、minimap、検索、経路比較、仮配分／リセットを保持。
- 起点は中央メイジ、左上タンク／左下戦士、右上レンジャー／右下アサシン。左右2組の起点と初期50点の表示位置を鏡像にした。効果・接続本数は職ごとに異なり、存在しない線を足して対称に見せない。
- 元の`graph.json`をHTML内にそのまま保持。表示用`display-layout.json`だけに投影座標・短い表示線・領域の外形を保存。ノードID、費用、効果、前提、全952接続、入力判定、配分処理は変更しない。
- Polish05の細い金属／真鍮の縁、落ち着いた色、承認済み日本語フォントとpixel sprite、背景画像を使用。武器・技の比較条件は開閉でき、必要なときに確認する。
- 完全に画面内にあるノードにはラベルを配置し、画面端で本体が切れるノードのラベルは無関係な位置へ飛ばさない。ノードとデータを削除する処理ではない。panで本体を画面内に戻せばラベルが表示される。

## 確認資料

`layout-verification.json` は全数・対称座標・線の距離・身体との交差を記録。`browser-verification.json` は実描画の645点／952接続、全47領域と5起点の52ラベル、初期50点の対称、75構造費用、同じ3ptの違う恩恵、仮配分→リセット、drag/wheel/pinch、検索、5職切替を記録する。固定UIで隠れたノードへのクリック・右クリック・ホイールが通らないことも確認する。

PNGは全域、5起点、戦士2経路、遠方領域、密度が高い領域、390px viewportの7枚。機械的な交差数だけで完成とせず、全体の線が長い折れ曲がりになっていないか、拡大時の経路とラベルが読めるかを目視する。線同士の交差は接続ではなく、pass-under gapを付ける。

生成は `python scripts/build-skill-tree-workshop-full.py`。スタイルだけを更新する場合は `--reuse-layout`。自分専用のChrome CDPが起動している場合に `node scripts/verify-skill-tree-workshop-full.cjs`。compile、実ゲーム起動、依存追加は行わない。

## 残る範囲

Creator本人による美術・操作感の採否確認、全ノードの専用pixel絵、Minecraft内の共通大盤面UI、新しい戦闘効果、保存・移行、実機での手触り・バランス確認。Windows Chromeとmobile viewportでの検証であり、iOS Safari実機の検証ではない。HTMLから実ゲームに反映したとは扱わない。

Libraryへの送信は本人の宛先確認待ち。追加アップロードは行っていない。この全域版はローカル成果物として保管する。

見た目と表示座標の入口は `proposal.js` / `proposal.css`。データ保全は `proposal-manifest.json`、配置と描画の問題は2つのverification JSONを最初に見る。

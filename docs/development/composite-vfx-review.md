# 連続発動・周囲への表示の確認

2026-09-08 / `play/gyai/class-combat-rework`。全技の実機品質は未承認。

## 修正した問題

周囲のプレイヤーへの8主表示枠を、古い順に、表示前の部品や遠くの部品まで数えていた。
そのため新しい攻撃を出しても、古い残光が枠を使い切る間は周囲から見えないことがあった。

`CoreCombatMeshes.tick` で、各観察者にとって近い・寿命内・表示開始済みの主部品を
新しい順に選ぶ。本人の表示、FULL/SUBDUED/MINIMAL、主表示8、本人48、シーン384の上限は維持。
表示を増やす変更ではなく、既存の枠を新しい動作へ割り当てる修正。
サーバーのダメージ・命中・スキル時間と、共有Particle Frameworkは変更していない。

自動テストでは実Minestomのメモリ接続で本人と近距離・遠距離の観察者を用意する。
先に複数の旗を表示し、その後の閃光歩の主放電4本が近い観察者へ届くこと、
遠い観察者が自分に近い旗を見続けること、表示前の新部品が枠を奪わないこと、
最小設定が表示を無効化することを検査する。実クライアントの描画確認とは別。

## 全職の連続投影

`CoreCompositeVfxReviewTest` は70技の基本カタログについて、最初の予備動作、
8tick間隔の全PULSE、FIELDの次の波に先立つ4tickの予備動作を重ねて出力する。
この間隔は `CorePlayerCombat.tick` と対応。サーバーを操作して記録したリプレイではない。
固定位置の術者・妨害なし・基本キャスト速度を仮定する。FIELDは最大6m前方を照準地点とする。
CONTACTを勝手に追加しない。実移動、装備補正、敵の反応、壁、予算による省略は含まない。

出力 `.tools/composite-skill-frames.json` は技ごとのイベント時刻・主副区分・波番号・最大部品数も持つ。
`scripts/preview_skill_choreography.py --ticks 10,24,40 --view eye` で必要な時刻だけ確認できる。
既存の連番GIF出力も維持。モデル・ポーズ・テクスチャは配布物そのものを使用するが、
立体面の色は近似、照明・遮蔽・通信・Minecraftのカメラそのものを再現しない。

連続構成の最大同時部品は絶対零界48、天球崩壊45、天火44、狩場40、星雲36。
これはCONTACTや他のスキルを加える前の値。上限に近いので、素材の単発投影だけを
もって多人数でも新しい攻撃が十分に読めるとは判定できない。

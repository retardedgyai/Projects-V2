# 戦闘VFX：時間演出の検証記録

2026-09-08 / `play/gyai/class-combat-rework` / **品質目標は未達、改修中**。

## 目標と今回の範囲

目標は全技を Crimson Moon / Wynncraft を参照した高品質な演出にすること。
形状数・テスト数・表示秒数を増やしただけでは完了にしない。
今回のチェックポイントは、静止PNGの出現／縮小から、速い主動作と長い
分解軌跡を分けること、前方軸と回転中心の修正、連続フレームQAの導入。

### ピクセル表現への訂正

「それピクセルじゃなくね？」という指摘を受け、滑らかな旧原画は使用停止。
新しい独自生成原画から、64×64・4色＋透明・ぼかしなしの16枚へ差し替えた。
階段状の輪郭、太い刃の塊、分解する角ばった破片を使う。詳細・生成プロンプトは
`assets/combat-vfx/README.md`。UIアイコンと日本語フォントは変更していない。

書き出しでは全辺4pxの透明余白を保証する。生成原画の不均一な行間は
明示的な切り出し座標で扱い、隣のフレームを巻き込まない。
以前のセル端切れの懸念はこの置き換えで解消した。

目線高1.62mからの簡易投影で、横斬りの面が水平、縦斬りの面が視線と平行で
線に潰れる問題も確認した。斬撃方向は維持して面に傾きを加え、残光には別の角度を付けた。
横斬りは幅を読めるようになった。縦斬りは依然として細めに見え、実機確認が残る。

をブラウザで再生・停止・コマ送りして確認した。以前の再生失敗とは別の観測。

- 0:58付近：白と灰の細かな塊が前方へ分散し、人物と地形を含めて奥行きが読める。
- 1:04付近：緑・黄の細い二重の線が場面を横切る。面で画面を埋めるのとは違う射線の表現。
- 1:09–1:10付近：足元の高密度な白い表現と、その上の分離した粒子・立体物が重なる。
  コマ送りで各粒子の位置・人物・カメラの変化を確認。トレーラーのカットが入るので、
  ここから正確なスキル寿命や全消散時間は推定しない。

参考から採る判断軸は、単純な粒子数ではなく「攻撃方向・標的・奥行きが読めるか」。
この解釈は作者の内部実装の説明ではなく、確認した映像に対する制作上の判断。
素材やゲームの内部コードを取り込んだものではない。

## 現行の流れ

1. `CorePlayerCombat` の確定した予備動作／攻撃波／命中を受け取る。判定は変更しない。
2. `CoreCombatMeshArt` が技の形・用途・寸法のベースを決める。
3. **`CoreSkillChoreography`** が主動作、遅延した残光、移動曲線、モデル連番を決める。
4. `CoreCombatMeshes` がVanillaのItemDisplayに実際のモデルと変換を送る。
5. `CoreSceneParticles` も同じ時刻の座標から粒子を補い、帰還／切断でまとめて破棄する。

最初に調べるファイルは `CoreSkillChoreography.kt`。向きだけがおかしい場合は
`CoreCombatMeshes.kt` の右回転補正と `build_core_combat_models.py` のUVを確認する。

### 寿命と動き

- 70技＋通常3段に明示的な時間を割り当て。通常16/16/24tick、スキル18–40tick。
  構えの本体は実持続時間を優先する。1tick = 0.05秒。
- 斬撃は16枚の連番。主刃の山場はローカル4tick、後半は分解した残光。
  表示全体が長くても攻撃判定は遅らせない。
- 返し刃はUV左右反転と逆回転。画像上端がモデル+ZになるようV軸を反転。
  Vanillaの `FaceInfo.UP` の最初の頂点がMIN_Zであることをローカルclient jarで確認した。
- 正面斬りは胸前、回転斬りは本人中心で6tickに一周。残光は別の面に遅れて出す。
- 断命は二枚の立った交差刃、毒牙は元の二本の牙＋小さな毒の軌跡を維持する。
- 吸引は消える前に中心へ収束。構えの主要モデルは有効時間の途中で分解しない。
- ネイティブモデルは7段階の部分除去。シェーダーの半透明フェードではない。
- 非同期スポーン完了を待って時計を進める。表示前に寿命を使い切らないよう
  ゼロ倍率でスポーンし、2tickの準備後に表示する。

### 上限

本人48体、同一インスタンス384体。他人に見える主要モデルは各キャスター8体まで。
新しい主刃が本人上限で消える場合は古い補助層を先に捨てる。粒子の既存予算は据え置き。
全パーティー実負荷を計測済みという意味ではない。

## 検証方法と限界

`CoreSkillChoreographyTest` は全70技の毎tickの実ポーズを
`.tools/skill-choreography-frames.json` に出力する。

```powershell
.\gradlew.bat :server-minestom:test --tests '*CoreSkillChoreographyTest' --offline --no-daemon '-Pkotlin.compiler.execution.strategy=in-process'
python scripts/preview_skill_choreography.py
python scripts/preview_skill_choreography.py --view eye --prefix pixel-eye-review
```

PNG/GIFは配布JSONの形状、連番テクスチャ、UV、配色と実ポーズを投影したもの。
**Minecraftの実画面ではない。** 後処理ブルームを足して良く見せてはいない。
目線プレビューは透視投影、等角プレビューも含めテクスチャは最近傍で描く。
至近距離の面は簡易的な奥行きクランプのため、回転技が画面端に伸びる表示は
実機で同じになることを意味しない。
地形による遮蔽、半透明の描画順、視点至近距離、パケット遅延、実FPS、音は証明しない。

追加テストは全技の参照先、8方位の正面斬撃、回転中心、UV反転、主刃の早い山場を確認する。
既存テストは命中線、予算、キャンセルなどを確認する。テスト合格は美的品質の合格ではない。

このチェックポイントでは `:server-minestom:test :server-minestom:distZip` が成功。
682件、失敗0件、エラー0件、スキップ0件（2分42秒）。追加のピクセル形式・余白と
本人目線に対する主刃の面の向きも合格。起動済みのサーバーとは別にビルドしており、
新しい原画／傾き修正を含むこの版のゲーム内手動確認はまだ行っていない。

## 残っている作業

### 星術の破裂チェックポイント

独自のピクセル連番 `stellar-burst-pixel-v1.png` を追加。
星降る夜／天球崩壊は予備動作の落下核を維持し、着弾後の静止核と図形状の星環を
二面の星光破裂へ置き換えた。地面の枝状図形も分解する光に変更。
星糸・星の針・星砕きは確定命中でのみ大小の破裂を表示し、星の針の印を残す。
守り・転移・星雲に破裂を使わない。適用は5技の発動／命中で、全技完了ではない。

新原画のフレーム03が2tickで最も明るくなり、その後は中空の渦と破片へ移る。
主面と青い残光は角度90度差・時間2tick差。通常命中は16tick、星砕き24tick、
星降る夜32tick、天球崩壊38tick。ダメージやクールダウンは一切変えていない。
詳細は `assets/combat-vfx/stellar-burst-pixel-v1.md`。

全テスト＋distZipは初回統合で成功（4分4秒、地面の追加修正前）。最後の地面置き換え後は
戦闘VFXのtargetedテスト30件・失敗0件・スキップ0件＋distZip成功（43秒）。
配布モデルと実ポーズの連続投影も再確認。実機での確認は未実施。

### 設置型の流れ・成長チェックポイント

星雲の平面図形＋星座を、6本のピクセル雲筋＋3つの小さな星節へ置き換えた。
3段の高さと時差を持ち、範囲内を流れてほどける。爆発・落下の素材は使っていない。
氷の庭は底支点の立体氷晶群8か所が段階的に成長する。その場を周回する柱や
中心の大きな雪結晶は使わない。判定・持続時間・クールダウンは変更していない。

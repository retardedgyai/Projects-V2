# 装備＋30強化・鍛冶熟練 v0

対象: `play/gyai/core-enhancement`。武器／防具それぞれを＋0から＋30まで繰り返し強化する。
「無限に強化」は今回、＋30到達まで反復操作できるという意味に限定し、無限インフレを導入しない。
装備Tier、レア度、ランダムMODとは別の成長軸。UI／戦闘は公開APIを統合側で消費する。

## 確認した旧仕様と今回の差分

参照元: 旧ProjectS `6f8d223` の以下を読み、現V2 `cbee1a2` と比較した。

- `docs/design/equipment-system.md`: 製造ベース・Tier・MOD空き枠の意図。
- `docs/beta/tracks/track-e-enhancement-tier-repair.md` と `docs/beta/wave-2-owner-decisions.md`:
  ＋0..30、変更提案を作ってから原子取引で確定。v2の確率・費用・移行方針は未承認policy入力。
- `enhancement/v2/*`: attempt／policy／proposal／resolver／transition／transaction adapter／legacy reader。
  policyは完全な成功・維持・降級・破損の分布と遷移を要求するが、本番数値を持たない。
- `EnhancementManager`、`EnhancementListener`、旧v2テスト:
  旧稼働実装は＋1〜5=100%、＋30=1%、費用ceil(目標値/5)の強化石。
  失敗時は維持、現在＋15以降は別抽選で破損し、修理するまで攻撃不能。天井・保護なし。
  攻撃倍率`1 + level*0.04`、攻撃速度`level*0.008`。

今回の実験値は旧v2の承認済み本番数値ではない。旧稼働版の成功率カーブを明示的に採用し、
**破損／降級を持ち込まない常設保護と、失敗天井、採取素材での費用**へ変更する。
装備が壊れてテスト継続不能になる流れや、良いMODを失う流れは作らない。
採取・製作との接続のために追加する概念は、以下の**鍛冶熟練／任意触媒の2つ**だけ。
今回旧PaperアイテムやPDCは読み書きしない。現コアループの個人台帳のみを拡張する。

## 強化の操作と効果

`CoreAction.EnhanceEquipment(gear, mode)`。拠点限定、武器と防具を別々に持つ。
成功なら＋1、失敗なら同じ＋値。両方とも支払った素材は消費され、鍛冶経験＋1。
失敗も保存済み取引としてCOMMITTEDであり、強化成功を意味するstatusではない。
UIは返却された装備状態と日本語結果メッセージを見る。連打の各試行は別requestId、
通信・保存再試行は同じrequestIdを使い、staleを勝手に新しい有料試行へ変えない。

| 対象 | 1段階の増分 | ＋30の効果 |
|---|---|---|
| 武器攻撃力 | 基礎に対し＋4% | 倍率2.2 |
| 武器攻撃速度 | ＋0.8ポイント | ＋24% |
| 防具の基礎最大HP | 基礎に対し＋2% | 倍率1.6 |

武器攻撃力とASは旧式を採用。防具HP倍率は今回の暫定追加。
純粋なproviderとして公開し、`CoreAffixStats`を変更しない。統合側は同じ効果を二重に掛けない。
上限が＋30なので最高効果も有限。素材Tier更新・オーブ全再抽選・洗浄でも、強化値と天井を保持。
逆に強化してもMODの種類／数値／Rank／ID、レア度、装備Tierを変えない。

## 成功率と天井

| 目標＋値 | 基礎成功率 | 失敗天井 |
|---|---|---|
| ＋1〜5 | 100% | 元から確定 |
| ＋6〜10 | 95, 87.5, 80, 72.5, 65% | 4失敗後の次回保証、最大5試行 |
| ＋11〜15 | 55, 50, 45, 40, 35% | 6失敗後の次回保証、最大7試行 |
| ＋16〜20 | 30, 26, 22, 18, 14% | 同上 |
| ＋21〜25 | 10, 8.5, 7, 5.5, 4% | 9失敗後の次回保証、最大10試行 |
| ＋26〜30 | 3, 2.5, 2, 1.5, 1% | 同上 |

実際の成功率=`min(100, 基礎＋熟練rank＋任意触媒15)`。全て%ポイント加算。
天井時は100%。天井は装備別の「次の＋値への連続失敗回数」で、成功時だけ0へ戻る。
失敗回数は保存され、メニューを閉じる／再接続／再起動／装備Tier更新では消えない。
＋0〜30は最悪でも200回の有料強化で到達する（素材が足りない操作は試行に数えない）。
`quote.guaranteed` は天井に限らず合算100%の場合もtrue。元から成功保証なら触媒は不要。
FOCUSEDを明示的に使えば触媒を消費するので、UIはSTANDARDを推奨する。

## 費用と任意触媒

u=`ceil(目標＋値/5)`、1〜6。全て**現在の対象装備Tier**の精製素材を使う。

- 武器: インゴットu ＋ 板材ceil(u/2) ＋ 加工石材u。
- 防具: なめし革u ＋ 布ceil(u/2) ＋ 加工石材u。
- 任意FOCUSED: 上記に同Tier加工石材1 ＋ 同Tier布1 ＋ 全体共有の刻印粉2を追加し、成功率＋15ポイント。

触媒は新しい通貨や収集袋を増やさず、加工方法の選択として必要素材を直接使う。
不足時の部分消費はしない。防具の基本布と触媒布は同じ残高キーへ合算する。
費用はサーバーが保存直前に再計算する。UIが送った価格や古いquoteを正本にしない。
T4到達後も5採取素材すべての精製品が強化／触媒／既存製作に必要になる。
採取が必須でない戦闘ルートは既存の券→同Tier素材交換で維持する。

## 鍛冶熟練（確定成長）

- 精製Refine: 1batchで1XP。
- 製作Craft: 1batchで1XP。薬2個出力でも1batchなので1XP。
- Tier更新: 武器／防具とも1回5XP。
- 強化: 成功・失敗を問わず素材を消費した1試行で1XP。
- 素材交換、地図取得、オーブ加工、拒否／保存失敗／重複再送は追加XPなし。

20XPごとrank＋1、最大rank10／XP200。rankがそのまま強化成功率への追加%ポイント。
低Tier素材の反復加工でも確定で育てられ、素材を消費して加工する意味を持たせる。
採取専用ジョブやスキルツリーを新設するものではない。rank10後の費用割引や追加インフレはない。
`masteryProgress` は通常0..19、rank10なら満了20を返す。

## 台帳と移行

schema4に `weaponEnhancement(level,failures)`、`armorEnhancement`、`smithingXp` を追加。
既存schema1〜3は読み込みだけでは書かず、初回成功保存前に元の完全一致backupを作る。
schema3は `<uuid>.account.v3.bak`。既存backupを上書きせず、不一致なら更新を拒否する。
旧形式に存在しなかった強化・熟練だけ0から開始し、素材・地図・MOD・Tier・レア度・通貨・
欠片・craftingSeed・レシート・受取元を保持する。schema4は強化row欠落／重複／範囲外を拒否。

費用控除、強化結果、天井、XP、レシートが同じimmutable proposalへ入り、原子的保存後にのみ
メモリの正本を置き換える。保存失敗時はすべて元のまま。
同じ操作の乱数は保存seed・playerId・revision・server requestId・装備・mode・policy revisionから
決定するため、保存再試行で有利な結果へ引き直さない。

## 主要APIとテスト

`CoreEnhancementCatalog.quote` は現在／目標＋値、成功率の内訳、天井、費用、拒否理由を返す。
未来の抽選結果は含まない。`state`、`masteryRank`、`masteryProgress` と3種類の戦闘providerを公開。
不具合時はまず `CoreAccountService.EnhanceEquipment` と `CoreEnhancementCatalog`、
再接続時の消失なら `CoreAccountRepository/CoreAccountCodec` を確認する。

`CoreEnhancementTest` は全30段階の確率・全4Tier費用・200試行以内の到達・天井・
触媒合算・熟練上限・保存失敗・再接続・重複／stale・旧MOD保全・schema3移行／破損保護を検証する。
加えて既存のCoreAccount／Affix／CraftingCurrency／RewardQueue testsを回帰実行する。

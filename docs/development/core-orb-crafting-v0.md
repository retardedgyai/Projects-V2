# 装備のオーブクラフト・探索イベント報酬 v0

対象: `play/gyai/core-orb-crafting`。既知のMODが入った刻印石を拾う方式を終了し、
拾うのは効果未確定の「加工用通貨」、MODの種類と数値が決まるのは装備へ使った瞬間とする。
PoE型の遊び方をProjectSの短いコアループに合わせた試作であり、PoEの厳密な再現ではない。

## 既存資料から維持した部分と今回の変更

- 旧 `docs/design/mod-system.md` の攻撃／スキル資源／防御／機動と16種の実効statは維持。
  旧MOD契約のID・Rank・数値範囲・出現部位・未知MODの効果停止も維持する。
- 旧 `equipment-system.md` の「製作した装備を使用者がMODで仕上げる」は維持。
  Common〜Epicの1〜4枠をTierへ結びつけたv0仕様は今回撤回する。
- 旧取引契約の「支払い・出力・保存・確定が一度だけ」「見た目は正本でない」は継続。
- **今回の独自追加**: Tierと独立の3段階レア度、接頭／接尾制約、12種類のオーブ、
  裂け目／儀式／試練の活動報酬、欠片3枚入場と専用ボス報酬。
  通貨名・確率・個数・上位25%・レシピは全て調整用の暫定値。
- 採取素材、精製、装備T1〜4、地図MOD、戦利品券交換は変更しない。
  装備は当面「武器1個＋防具セット1個」の抽象モデルを維持する。

## 装備の枠

| レア度 | MOD上限 | 接頭上限 | 接尾上限 |
|---|---:|---:|---:|
| ノーマル | 0 | 0 | 0 |
| マジック | 2 | 1 | 1 |
| レア | 6 | 3 | 3 |

T1装備でも6MODのレアを作れる。Tierは新しく付くMODの数値範囲だけに影響する。
T1からT2へ鍛造しても既存MODの種類・ID・Rank・数値・レア度はそのまま。
新たな追加や全再鋳造では現在の装備Tierの範囲を用いる。
同じ装備内の同一MOD IDは重複しない。武器と防具の両方に同種を付けることはできる。
守護・軽歩は防具専用、他は両部位。戦闘側の既存上限を維持し、上限超過分を効果として偽表示しない。

接頭: 攻撃力、スキルダメージ、通常攻撃ダメージ、最大マナ、最大HP、火・氷・雷。
接尾: 攻撃速度、マナ回復、CD短縮、被ダメ軽減、移動速度、クリティカル率増加、倍率、キャスト短縮。
接頭／接尾は表示と枠制約であり、新たな計算層ではない。

## 通貨操作

全て1回につき1個消費。拠点限定。未所持・対象のレア度違い・満杯などは無消費で拒否する。
事前画面には操作の説明・費用・現在装備だけを表示し、**次に付くMODは一切表示しない**。
結果は保存成功後に現在装備として表示する。全再抽選と洗浄は元のMODを失うためUIで明示する。

| 通貨 | 条件 | 確定後の効果 |
|---|---|---|
| 変成 | ノーマル | マジック化、MOD1〜2個 |
| 増強 | マジック・空きあり | 既存を保持してMOD1個追加 |
| 改変 | マジック | 既存を全削除してMOD1〜2個 |
| 錬金 | ノーマル | レア化、MOD4〜6個 |
| 混沌 | レア | 既存を全削除してMOD4〜6個 |
| 富豪 | マジック | 既存を保持してレア化、MOD1個追加 |
| 高揚 | レア・空きあり | 既存を保持してMOD1個追加 |
| 洗浄 | マジック／レア | 全MOD削除、ノーマル化 |
| 神聖 | 対応済MODあり | 同じMOD・Rank・IDの数値だけ再抽選。低下し得る |
| 裂け目 | 任意のレア度 | 元を全削除しレア4〜6個へ。火／氷／雷を1個以上保証 |
| 儀式 | 対応済MODあり | 各MODの値を2回抽選し大きい方。元の値は保証せず低下し得る |
| 試練 | レア・空きあり | MODを1個追加。数値は範囲の上位25%（整数切上げ） |

全再抽選の個数は指定範囲の整数一様分布。MOD種類は利用可能な定義のweightを用い、
現時点では全16種類weight10。範囲内の整数値も一様分布。
神聖／儀式は元のRank範囲を使い、装備Tier更新だけでは旧MODのRankを上げない。

## 通常ドロップと特殊活動

`CoreCraftingCatalog.rollLoot` は装備の抽選ではなく地面に出す**通貨だけ**の決定的プレビュー。
通常敵: 35%で1個、エリート: 2個、ボス: 3個。同通貨が重なれば数量として集計する。
普通の敵は通貨0個でも刻印粉1＋同Tier戦利品券2を落とす。
エリートは粉3＋券6、ボス追加ドロップは粉6＋券0（券12はBossReward側）。
旧石袋256個の上限は新通貨ドロップに影響せず、旧石を自動破棄／変換しない。

通常通貨weight（合計100）:
変成18、増強15、改変20、錬金12、混沌10、富豪8、高揚4、洗浄9、神聖4。
裂け目／儀式／試練は通常ドロップから出ない。

通常マップの `ActivityReward(runId, sourceId, kind)`:
対応する専用通貨1個＋同kind入場欠片1個＋同Tier券3枚。
sourceIdが同じならkindを書き換えても二重取得不可。
専用ボス戦内に通常マップ活動報酬を再出現させてはならない。

通常マップ `BossReward` は従来の次Tier地図・解放・討伐証2・券12・採取石板1・薬2を維持し、
**試練の欠片1個を必ず追加**する。これで3回の通常ボス討伐から試練へ到達でき、
試練内でしか入場素材が取れない循環詰まりを避ける。

## 専用ボス入場・帰還

`StartTrial(bossId, tier, runId)` のbossIdは `rift` / `ritual` / `trial` のみ。
拠点・解放済Tier・未使用runIdを台帳で検証し、対応欠片3枚を消費する。
通常の所有地図は消費せず、専用の仮想地図と `activeRun.trialId` を一括保存する。

準備／転送失敗の `AbortRun` だけ欠片3枚を返し、仮想地図を保管庫に入れない。
獲得報酬が1件でもある場合はAbortによる入場料返却を拒否。
通常帰還・死亡・切断・再起動からの回復は `FinishRun` で終了し、欠片を返さない。
専用ボス討伐は対応通貨2個＋高揚1個＋同Tier討伐証2＋券12。
通常地図やTier解放は発生させず、通常ボスの追加報酬へすり替えない。
通常 `AffixLoot(BOSS)` の追加通貨3個は別の受取元であり、統合側が可視ドロップを出した場合だけ受け取る。

## 旧データ保全と保存契約

- v1/v2読み込み時はファイルを書かない。初回成功更新前に元ファイルの**完全一致コピー**を
  `<uuid>.account.v1.bak` または `.v2.bak` へCREATE_NEWで保存し、既存backupを上書きしない。
  既存backupが異なる場合はfail-closed。新しい本体はschema3で原子的置換。
- 素材、Tier、地図、アクティブ遠征、レシート、報酬受取元、旧石、装着MODのID/値/位置を保持。
  旧2枠に接頭2個、旧4枠に接頭4個などはlegacy-layout印で保持し、戦闘効果も維持する。
  その装備へ追加する通貨は拒否し、全再鋳造／洗浄で新制約に移せる。
- 旧未装着石は「旧石の交換」に隔離。本人の明示 `ConvertLegacyStone(stoneId)` で
  改変×石Tier＋錬金1へ交換する。既知石のみ対応し、未知定義／未来revisionは保管のまま。
  旧直接付与・抽出・石再抽選・石分解のactionは終了メッセージで拒否する。
- 乱数はserver-owned操作UUID＋account保存seed＋playerUUID＋revision＋対象と通貨で決定。
  同一操作の保存再試行・再起動でも結果を変えず、費用と結果は同じ原子更新になる。
  staleを自動的に新操作へ変えてクラフトを再実行してはいけない。結果不明のretryは同じUUIDを使う。
- 通貨・欠片は独立したenum残高で、ItemStackや表示文字を正本として保存しない。
  1種類上限1,000,000。上限超過時も費用／報酬元／装備を半更新しない。
- `CoreRewardQueue` は活動報酬もsource単位で重複排除し、保存が回復するまでdrainを待たせる。
  帰還前に新規報酬producerを止め、可視ドロップを回収submitしてからdrainする。
  未保存queueはメモリなのでdisk障害中のプロセスクラッシュには永続保証を偽らない。

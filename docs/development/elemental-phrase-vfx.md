## 素材と動き

`scripts/build_core_combat_models.py` の `molten_core` と `build_elemental_phrases`。
Minecraftの立体モデルとして、段状の輪郭・離れた炎先・体積のある分岐を作る。
新しい画像生成や外部素材の取り込みではない。既存UI・フォント・スキルアイコンは変更しない。
炎柱は根元から立ち、後半は根元が消えて先端が分離する12種類のモデル。
火球の尾は同じ炎の構成を進行方向の後ろへ向けて正規化した別モデル。
隕石の破片は上方の曲線軌道から降下し、回転しながらほどける。
霜波は広い段状の弧を持つ専用素材。設置型の氷の庭のような柱は使わず、
外向きに進みながら波頭が欠けて消失する。

実判定 → `CoreSkillChoreography.parts` → `fireLanding` / `frostWave` / `stormDischarge`
→ `pose` が位置・コマを決定 → `CoreCombatMeshes` がItemDisplayを更新。
炎の落下は従来のPREPARE、崩壊はPULSEに属する。演出都合でダメージを遅らせない。
火炎弾は従来の射線の中心・長さ・角度を維持する。独立したゲーム判定やタイマーを追加しない。

異常時はまず `CoreSkillChoreography.kt` の上記3関数と `pose` の専用モデル選択を見る。
立体形状ならモデル生成スクリプト、音なら `CoreSkillAudio.kt`。
本人48体／全体384体の上限は維持。今回の1演出は最大12体。

## 検証と残件

追加テストは落下と着弾の分離、炎12コマ、破片の上昇・降下、全ピッチの短い射線、
低い全周霜波、雷の8コマ、モデルの立体体積と火炎尾の境界を検査する。
全技の全フェーズに対する配布モデル参照検査も継続する。

連続投影は配布モデルとKotlinの実ポーズによる簡易QAであり、Minecraft画面ではない。
実機での坂・段差との重なり、多人数での視認性・負荷、音と手触りの最終評価は未実施。
ゲームの自動操作・起動・再起動は今回行わない。

最初の統合で全699テスト・失敗0件・エラー0件・スキップ0件＋distZip成功（3分56秒）。
連続投影で霜が離れた氷柱、雷が直線の放射図に見えたため、
霜を幅広い弧状の専用波頭へ、雷を大きく折れた非対称の分岐へ修正。
炎も幅と芯の明るさを調整した。最終差分の関連45テスト＋distZip成功（57秒）。
修正後の連続投影も再確認した。これは実機での品質承認ではない。

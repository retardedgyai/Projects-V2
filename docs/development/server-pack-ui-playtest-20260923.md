# サーバー配信UI・ゲーム内比較試作

Vanilla Java 26.2向けのサーバー配信リソースパックで確認する。クライアントMODは不要。装備の形、文字、操作の優先順位を、実際のGUIスケールとホバー状態で判断するためのPlayground試作。

## 今回の変更

- 工房と周辺メニューの背景を暗い青みのある石板色に揃えた。ランダムな表面ノイズを取り除き、境界はピクセル単位の段差と短い線にした。
- 選択中の操作は明るい無彩色、実行は温かい金色、不足は鈍い赤色にした。レア度の緑・青・紫は装備とツールチップの情報に使う。
- 強化画面の対象アート脇に、マジックとレアの小さな色印を加えた。既存の武器絵は塗りつぶさない。
- `/uipreview` は4段階の既存大剣モデルとレア度別ツールチップを並べる読み取り専用画面。見本を持ち出せず、クリックによる消費や制作もない。「工房へ」から本来の操作画面へ移れる。

色の役割を「選択・実行・危険・レア度」で分け、アイコンの形と日本語の判読を最優先する。これは[RiotのClarity in League](https://www.leagueoflegends.com/en-gb/news/dev/clarity-in-league/)の視認性と情報階層の考え方を、Minecraftの18pxスロットに合わせて適用したもの。外部作品の画像は追加していない。

## ゲーム内確認

1. このブランチの `server-minestom` をJava 25で起動する。待受は `127.0.0.1:25565`、パック配信は `127.0.0.1:25566`。
2. Java版26.2で `localhost:25565` へ入り、サーバーリソースパックを承認する。チャットに「ProjectSのUIを適用しました。」と出ることを確認する。
3. `/uipreview` を開き、4つの武器の形が判別できるか、レア度色が強すぎないか、全てのホバーツールチップを確認する。
4. 「工房へ」から、強化・精製・制作・刻印、武器・防具、素材不足、実行ボタンを見る。強化ではマジック／レア装備の場合だけアート脇に色印が出る。
5. GUIスケールを変えて、日本語の潰れ、アイテムとボタン文字の重なり、ツールチップの画面外はみ出しを確認する。

この試作の最終的な視認性と操作感はCreatorがゲーム内で判断する。オフラインの画像はホバー、Minecraftの3Dモデル描画、実画面スケールを再現しない。

## 実装・調査位置

`scripts/build_core_menu_assets.py` が外枠と操作ボタン、`scripts/build_core_ui_assets.py` が工房背景、`CoreMenuCanvas` が表示色、`CoreLoopMenus` が工房と比較画面、`CoreLoopServer` が比較コマンドを持つ。パック配信は既存の `CoreUiPackServer`。パック未適用時も通常のチェスト操作と日本語の説明を残す。

構造検証は `scripts/verify_core_ui_assets.py`、表示処理の回帰は `:server-minestom:test --tests dev.projects.server.coreloop.ui.*`。実ゲームでの見え方が不適切なら、色の変更より先に背景・文字・アイコンの競合箇所を特定する。

# Essentia充填に連動する核と中央アイテムへの注入

最新本人指示に基づく別演出版。`-BudgetedEnergy -ChargedCore -PowerPerSecond 18` で既存のE/Pモードに局所的な演出だけを追加する。前版モードと旧比較は保持。必要総量120E・供給0/6/18の仮設定、通常素材4品、Jar消費火3/水2/風2、固定MOD1枠変性・保存トランザクションを変えない。

核の充填は保存済み `supplied` の各元素の消費済み量を必要量で上限処理し、合計/必要総量で計算する。現在の同時波は0→3/7→6/7→7/7。秒数・供給値・未消費のJar在庫で満タンにしない。充填に応じ紫刻印のnative tintの基準明度が0.22→0.90、脈動幅0→0.05、既存半透明spriteの核周囲粒子が0→16へ増える。核・支柱・台・Jarのgeometry/UV/PNGは不変。

全Essentiaが供給され、煙が到達してから副素材吸収。最後の100→120Eの段階で核の下側から中央アイテムへ24個の紫の煙の節が降りる。注入先端の位置は保存済みEの実投入進捗に連動し、経過時間で完了させない。既存の完成後の台座紋様→立ち上がる光は着地の応答として同期。白い全画面光や武器メッシュの差し替えは追加しない。

P=0または不足停止では既存充填を保持した明度に固定し、増加脈動・核粒子・新規注入粒子を止める。実表示の粒子更新は既存2tick周期なので既存の核粒子撤去に最大2tick。既に放出されたJar煙は従来どおり到達して消える。再開/再読込で受領済み量を再利用し、取消は新規演出を終了。再読込したCOMPLETEを成功イベントとして再発火させない。

核粒子/注入/既存成功演出/Jar煙は同じ64個/儀式のsprite制限を共有。中央の注入を優先して残枠にJar煙を表示し、台座の一時モデル1個を含め最大65個。全儀式で共有する既存192lease制限を維持。持ち物の取出し、破壊、切断、world unload、closeで既存cleanup経路を使う。

テストは充填と強さの段階、P=0での保存と明度不変、注入の下向き進行、同量資源、停止/再開/取消/再読込、実Minestom APIのnative表示・lease cleanupを確認する。GIF/PNGは同じKotlinのaccepted traceと実model/UVを使う独立レンダー。段階PNGだけは核を同じ向きに固定し、同じ充填値と核周囲粒子を回転移動して明度を比較する。GIFは実ロジックの回転を使う。新レンダーは毎フレームの原pixel面展開をcacheし、固定姿勢で旧native rendererとの一致も検証する。

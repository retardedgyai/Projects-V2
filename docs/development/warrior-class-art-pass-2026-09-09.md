# 戦士を一クラスとして整える：演出の第一稿

## 目的と判定

「全職へ一斉に増やす」を止め、戦士の通常攻撃・攻撃技・防御支援・武器・音を一つの戦闘体験として評価する。
このcheckpointは第一稿であり、実機feelは未承認（FIX-FIRST）。Crimson Moon / Dragon Warriorと同水準に達したとはしない。

直前の実プレイログ `core-loop-20260909-071640.log` に残った戦士の先頭節の最大サーバー更新間隔は約50〜53ms。
少なくとも記録された区間に大きなサーバー停止はなく、サーバーtick停滞だけで今回の不満を説明しない。
これはクライアントFPSや到着時刻の測定ではない。前の自作GIFを実機品質の代わりにしない。

## 戦士の共通方針

- 鋼の刃・短い白い残像が基本。金色は返し・重撃・防御支援の強い瞬間に使う。
- 残像は刃が通った場所に残る。完成した三日月全体を移動・回転・繰り返し再生しない。
- 素早い技、広い技、縦の重撃を輪郭・通る方向・余韻・音程で区別する。単に色だけを変えない。
- 受け流し→返し刃、裂傷→闘気を使う重撃、複数体→旋風という既存の戦い方を視覚で読みやすくする。
- 大剣の承認済み作画・持ち手・赤い刃の装飾、既存アイコン/HUDは維持。武器の色を理由に全技を赤くしない。

| 動作 | この稿の構成 |
| --- | --- |
| 通常1段 | 低い横薙ぎ。短い鋼色の残像 |
| 通常2段 | 逆方向への返し。1段の再生ではなく別経路 |
| 通常3段 | 斜めに見える縦の重撃。前2段より太い |
| 踏み込み斬り | 前方を広めに横断する一振り |
| 裂傷斬り | 小さく速い一振り。高め・短めの音 |
| 返し刃 | 逆方向の大きな金色の刃。低い音 |
| 地砕き | 前方への縦斬り。重い命中音はCONTACTのみ |
| 旋風斬り | 身体の周囲を回る3段。低い→高い→広い金色の締め。中心を前へずらさない |
| 破城突き | 前方へ伸びる細い直線。横薙ぎと区別 |
| 天断 | 斬り上げ→返し→縦の締め。説明文も合わせる |
| 受け流し・雄叫び・旗 | 既存の構え・声・旗を維持。支援発動で剣のRELEASE装飾を出さない |

## 実装・処理

最重要: `CoreWarriorBladeChoreography.kt`。

戦士の既存イベント → 戦士専用parts → 固定された8つの短い経路区間を順次表示 → 幅が細くなってその場所で消える → 最終補間後に削除。

各区間の位置・向き・モデルIDは生存中固定。成長・消滅はscaleで行い、Vanillaの2tick補間を使う。
別のPNG/モデルへの毎tick交換も、残像が次の位置へ追従する動きもない。
予備動作では大きな斬撃をもう一度描かず、手元付近の小さな光だけにする。
縦斬りは完全な真横の面にせず斜めにし、前方の横薙ぎには固定の浅い湾曲方向を持たせる。カメラ追従ビルボードではない。

新しいラスタ素材は追加していない。既存の短いflow部品（steel/gold）を組み直す試作であり、新原画を作ったとはしない。
ヒット・CD・消費・闘気・キャンセル・スキル枠・保存形式は変更しない。変更したカタログ項目は天断の説明文のみ。
他クラスは新ルートへ入れない。共有Particle Framework core、Class runtime共通基盤、protocol、クライアントは変更なし。

### 変更ファイル

- `CoreWarriorBladeChoreography.kt`: 10動作（通常3段＋攻撃7技）の経路・色・タイミング。
- `CoreSkillChoreography.kt`: 戦士専用ルートの選択。
- `CoreCombatMeshes.kt`: 新しい残像の補間終了待ちと、任意の先頭節タイミングログ。
- `CoreSceneParticles.kt`: 残像の中心に無関係な粒の雲を追加しない。
- `CoreSkillAudio.kt`: 軽い刃・返し・突き・重撃・旋風の段ごとの音を区別。
- `CoreArmamentPresentation.kt`: 支援技で剣を振った扱いにしない。
- `CoreSkillCatalog.kt`: 天断の説明文。
- `CoreWarriorBladeChoreographyTest.kt`: 新ルートの検証とVanilla検証用目標データ。
- 既存の斬撃テスト群: 旧描画方式のテストは旧実装を直接検証して保持し、現在の戦士に旧方式の形状数・動く残像を要求しない。全職の資源参照・境界検証は維持。

## 検証

- サーバー全テスト801件成功（ログ対応まで）。その後、天断の締めの地面余白と全段の境界検査を追加し、関連193件と実Vanillaの224ストリームを再実行して成功。
- Vanilla 26.2のDisplay実クラスへ全10動作・全段の112節を通常配送／1tick欠落で入力。224ストリームで有限の変形・最後の縮退を確認。
- 各区間の位置・方向・モデルID固定、段ごとの違い、旋風の中心、全段・8方位での形状の外接角の地面・前方・リーチ境界、他職の非変更を検証。
- `.tools/warrior-class-shape-*.png` と `warrior-class-eye-*.png` で斜め視点・目線高の形状を確認。静止投影であり実機の動きの証拠ではない。
- 失敗した縦斬りのリーチと天断の正面投影率は、テスト閾値を緩めず配置・面の向きを修正した。

## 手動評価と残る課題

次は技を増やす前に、戦士一クラスで以下をまとめて評価する。

1. 通常1→2→3が別々の絵ではなく一連の攻撃として感じられるか。
2. 裂傷→地砕き、受け流し→返しで、軽い仕込みと重い解放が区別できるか。
3. 旋風が身体の周囲で起き、移動・回避中断時に取り残された長い絵がないか。
4. 天断の3段が違う動作に見えるか。通常攻撃より強いが敵の予兆を隠しすぎないか。
5. 支援技が攻撃と見間違えられないか。

全身・腕の動作は既存Vanillaのまま。実際の大剣モデルを経路に沿って連続回転させる実装ではなく、ここが残像と一致するかは未達の確認点。
8区間による円形輪郭の角張り、移動時の身体と固定された残像の距離、厚み・密度の不足は引き続き実機で判断する。
自動テスト成功を「綺麗になった」「手触りが完成した」と読み替えない。次の改善対象はその実機評価から戦士内で一つに絞る。

異常時は新クラスのparts/pose → CoreCombatMeshes → 配信packのflow資源を確認。
`-Dprojects.vfx.traceTiming=true` なら `warrior_trace:tail` の更新間隔を記録できる。
今回、稼働中ゲームの操作・再起動・ライブpack差し替えは行わない。次の起動時にinstallDistと確認packを更新する。
`play/gyai/class-armament-art` にcommit・通常push。main、`.tools/`、`.kotlin/`はcommit対象外。

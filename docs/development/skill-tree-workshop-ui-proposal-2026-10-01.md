# パッシブツリー：工房の意匠を使う別UI案

「持っている武器・技・装備を、どう伸ばすか」を選ぶ育成。技そのものの習得は別の仕組みに置く。道中のSmallで得る恩恵を選び、Notableで方向を強める。Keyは強みと代償を伴う任意のルール変更案で、Keyを取らない配分も成立させる。

今回は5起点の一覧と、選んだ起点の最初の3ptを別画面状態にする案。5起点は中央メイジ、左右にタンク／アサシン、戦士／レンジャーを置き、同じ寸法のメダリオンで左右対称にする。数合わせの6起点は追加しない。職ごとに違う既存接続は、起点一覧に縮小混在させず、選択後の経路に表示する。

## 変更と保全

- `assets/core-ui/large-tree-preview/proposals/workshop-v1/` だけに別案を作成。元の大盤面HTML、graph、audit、Polish05工房原画・元UIは変更していない。
- Polish05の暗い金属、細い真鍮の縁、控えめな発光、日本語フォントを参照。承認済みpixel spriteを再利用。新しい全ノード用イラストを完成させたとは扱わない。
- 内包データは元の645点／952接続と完全一致。費用・隣接・効果・入力条件・配分処理は既存プレビューを使用。新しいアクティブ習得、装備制限、魔術加工必須条件は追加していない。
- 3pt例は同じNotableへ、異なる道中の能力を経て到達する。戦士では物理+12%経由とHP+8%経由。共通の終点は攻撃速度+5%、固有資源+4%の仮案。
- 終点の入力がない恩恵は灰色と「入力不足」で表示。すべての数値・新効果は比較用の仮案で、実戦には反映していない。

## 確認

`verification.json` に検証結果を保存。5職で既存の10点と全内部接続（戦士13、タンク16、メイジ17、アサシン13、レンジャー17）を確認した。各2経路は3pt、恩恵が異なる、実接続を通る、配分3pt→リセット0ptとなる。無関係なノードを線が貫く箇所と、描画されたラベル／ノードの交差は0。右パネルの配分ボタンとKey説明が領域内に収まる。

PNGは1600×1060で実HTMLから取得。起点一覧、戦士2経路、他4職を目視確認する。これは表示範囲の確認であり、47領域全体の密度が改善した証拠ではない。

再生成は既存Pythonで `scripts/build-skill-tree-workshop-proposal.py`。専用Chrome CDP `127.0.0.1:18126` を起動した場合のみ `node scripts/verify-skill-tree-workshop-proposal.cjs` と `node scripts/capture-skill-tree-workshop-proposal.cjs`。compile、ゲーム起動、依存追加は不要。

## 残る範囲

47領域／645点の全体配置、経路が多い起点の線の密度、効果ごとの専用pixel絵、Minecraft内UI、サーバーの戦闘効果、保存・移行、Creatorの実ゲーム手触り確認は今回の完了範囲に含めない。防具は全職自由混合とartifact別series、魔術は任意の装備MOD変性・専用MODの検討を維持する。育成の役割は既存の力を伸ばす選択で、それらの取得方法を置き換えない。

重要な実装は `proposal.js`。見た目は `proposal.css`、内包データ保全は `proposal-manifest.json` と `verification.json` を最初に見る。元の調査・未実装範囲は `skill-tree-data-preview-2026-10-01.md` と `large-skill-tree-route-preview-2026-10-01.md` を参照。

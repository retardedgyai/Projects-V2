# ProjectS パッシブツリー・全体構造の別案

## 依頼と位置づけ

本人の「スカスカなのが気になる、全体的な形の構造を改善できる？」に対応した、採用前の比較案。指定画像 `libfile_207828053bd48191bfabd38b31e47244` を実見してから作成した。小さな円形の領域が長い疎な通路の先に点在し、複数の大きな空洞があることを確認した。

原版は commit `c6a8c919` のまま保持。`graph.json`、既存の全域工房UI、承認済みPolish05の字体・sprite・背景は変更しない。今回の別案は `assets/core-ui/large-tree-preview/proposals/workshop-structure-v1/` にのみ置く。Minecraft本編への導入ではない。

## 骨組み

47領域を7本の帯と左右22組・中央3領域へ組み直した。5起点と初期50点を含む、全645点の表示座標が左右対称。領域は分岐、梯子、傾いた扇形、中央の対称な枝へ変え、閉じた円形の外枠を反復しない。全体の占有面積は原版の33.6%で、点数の追加はない。

各領域の汎用報酬の接続ノードから、そのまま近隣へ進むか、Smallを拾ってNotableを目指すかを選べる。近隣の横道と周回経路を接続し、Notableから任意のKeyへ寄り道する。Keyは旅の必須関門にしない。全5起点について、Keyを一つも使わず全ての通常ノードへ到達できることを構造で検証した。他職の起点を通過するショートカットは引き続き禁止。

パッシブは持つ武器・技・装備の伸ばし方を選ぶもの。技そのものの習得は別。防具の全職自由混合・artifact別series、任意の装備MOD変性・専用MODの検討を変更しない。敵名、コンテンツ、ボスや装備直ドロの仕様を追加した案でもない。

## 接続と取得費用

原版952接続に対し、この案は849接続。全645ノードのID、効果、費用、前提、入力条件、出典は原版と同じ。配置と接続は `candidate-graph.json` の別データとして変更する。原版の過去の配置・費用auditを新接続の証拠として使い回さず、新しい検証を保存した。

原版と案について各5起点×15Keyの75ケースずつを、独立した探索と実ブラウザの探索で照合した。2Keyの同時取得は各5起点×4組、計20ケースで、ノード費用を含む3端点Steiner最小費用を比較した。これは構造費用であり、入力条件を満たした実戦ビルドの強さを示さない。操作HTMLでは従来の装備・技の入力条件判定を残す。

戦士からの例:

| 目標 | 原版 | 別案 |
| --- | ---: | ---: |
| 守りの循環 | 22pt | 21pt |
| 不動の核 | 20pt | 22pt |
| 守りの循環＋不動の核 | 40pt | 32pt |
| 残火の持続＋雷の収束 | 40pt | 30pt |
| 氷の攻撃機会＋雷の収束 | 37pt | 37pt |

同じ物理火力Notableへの実データの経路例は、8ptでHP+18%/物理防御+16%/物理ダメージ+27%、9ptでHP+18%/物理防御+26%/物理ダメージ+22%。画面の既存換算値であり、道中の恩恵をどう配分するかが変わる。効果の係数は未採用。

複数Keyを安く取れる組があるため、採用時は48/64/80ptの予算、各Keyの条件・代償・相互作用を別に確認する。専用効果の実装や最終バランスが済んだと扱わない。

## 表示と検証

`ProjectS_Passive_Structure_Comparison.html` の「原版と比較」で原版／別案を切り替えられる。配分済みなら切替時に確認してプレビュー配分をリセットする。pan/zoom、検索、5職切替、2経路の比較、配分・リセットを保持した。専門領域を見ている間は初期50点の補足ラベルを省き、起点／初期ノードの確認時には表示する。ノードや効果を削除する処理ではない。

全域2枚、同じ領域の旧新2枚、5起点、390pxモバイルの計6画面で、ノード同士・ラベル同士・ラベルとノードの重なり、および配置できないラベルが0。全域では実際に645点、原版952接続／案849接続、52ラベルを描画した。固定パネルに隠れたノードへクリック・右クリック・wheelが通らないことも確認した。JS例外と外部リクエストは0。

ワールド配置ではノード衝突、配線とノードの衝突、非接続配線の同一直線上の重複が0。線の交差257か所にはpass-under gapを付けている。無交差の図ではない。全体の線密度・経路の識別しやすさは画像を見てCreatorが判断する。

生成: `python scripts/build-skill-tree-structure-proposal.py`。表示文言のみ更新する場合は `--reuse-layout`。検証: 専用Chrome CDP起動後に `node scripts/verify-skill-tree-structure-proposal.cjs`。比較画像の合成: `python scripts/make-skill-tree-structure-comparison.py`。compile、実ゲーム起動、install、main変更、push、deployは行わない。

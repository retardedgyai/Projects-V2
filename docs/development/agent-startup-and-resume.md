# 起動・再開時の指示範囲

起動時に、現在のcwd、実repo/worktree、適用されるAGENTSと下位指示、現在のTask契約を区別する。gitdirの共有先や参照repoのAGENTSを、別worktree・非Gitの制作フォルダへ自動継承される指示として扱わない。対象素材を生成するscriptが別階層にあっても、その素材の下位指示を確認する。

共通方針の管理元はこのrepoのAGENTS.md。変更は専用branchで保存し、既存worktreeの未整理変更や他担当の制作を巻き込まない。別worktreeへの反映は担当が既存差分を確認して行い、一括直接書換えをしない。稼働中ターンは親またはCreatorから必要な指示を明示し、ファイルの書換えだけで注入済み指示が更新されるとは仮定しない。

## 最新状態と履歴

- 最新のCreator指示を優先し、停止・再開・負荷順番待ち・採用待ちを別々に扱う。再開済みの作業を旧checkpointの停止文だけで止め直さない。
- 過去Task文書の「pushしない」は、2026-10-03の通常自動push許可に合わせて通常Git pushの範囲だけ更新する。ゲーム接続・main統合・本番deploy・公開設定変更の制限はそのまま保持する。
- 各制作の現行入口を一つ決め、旧checkpointの先頭からその入口へ案内する。旧記録は削除せず、どの部分が履歴かを明記する。
- 入口には対象候補のpath/版、現在有効な制約、最新の検証を指す。別版のPASSや撮影済み画像を現候補の検証へ流用しない。mtimeだけで採用版を決めず、候補と証拠の対応を確認する。
- 他担当が更新中の入口・制作物は勝手に編集せず、担当へ更新箇所を渡す。共有境界や負荷枠を待つ間も、依存しない許可済み分析・修正は続ける。

## 非Gitの独立制作フォルダ

担当が入口AGENTS.mdに次の短い案内を置き、現行Taskの保護対象と再開状態を併記する。repoへの接続を許可されたと推測せず、接続する場合は専用branch/worktreeを使う。

```text
ProjectSの共通方針は <担当が確認したrepo/worktree>/AGENTS.md を読む。
「これを作って」ではAgentが複数の実参照を選定・分析し、代表試作、同条件比較、反証、修正、最後の全体確認を行う。毎回の参照選定や内部試作承認をCreatorへ戻さない。
現行の候補・証拠・停止/再開/負荷待ちは <この制作の現行入口> を読む。旧checkpointは履歴として保持し、最新の明示指示を優先する。
既存ProjectS repo/remoteへの通常自動pushは許可済み。意味ある保存点と検証状態を示す。pushは完成・品質合格ではなく、main統合・force push・本番deploy・公開設定変更とは別。
```

# 天彗龍（バルファルク）の習作モデル

bilibili の動画「GPT6.2Astra制作的天彗龙 Blockbench模型」（游荡的Soul、BV1KSsS6JEu8、30 秒）と同じ品質に届くかを確かめる習作。
天彗龍はカプコンのデザインなので、ゲームのモブとしては登録しない。置き場は `assets/model-lab/valstrax/`（ビルドが変換するのは `assets/bosses/*.bbmodel` だけ）。
公式のモデルデータ・テクスチャ、動画の作者のファイルは使っていない。公開の絵と動画を見て、箱はすべて `scripts/build_valstrax_study.py` が置く。

```
python scripts/build_valstrax_study.py                      # assets/model-lab/valstrax/valstrax.bbmodel を書く（約 45 秒）
python scripts/boss_preview/valstrax_view.py out.png idle 0 # 窓を開かない確認用の絵（Blockbench・Minecraft の画面ではない）
```

## 作者はどう作っているか（調べた結果）

分かったこと（出どころ付き）。

- 説明文：「モンスターハンターライズの公式モデルを参考」「元は GPT6 Astra 作、GPT6.2 Astra が出てから直した版」。
- 作者のコメント：「これはテクスチャ寄りで、マイクラ風ではない。再現として作ったので、風格づけは後で」。
- 見た人のコメント：「約 500 個」「UV テクスチャは AI が貼った」「ボクセルを 1 個ずつ積んだ箱が残っている」。
- コマの拡大：鱗や濃淡が写真のようになめらかで、模様が隣の箱へ途切れずに続く。箱ごとに塗ったのではなく、元の立体の絵を箱の面へ焼いたときの見え方。
- 作者の別の動画（Create MOD の再現）：「公式の倉庫からテクスチャを取らせた」「少しずつ食べさせて作った」。
- 同じ界隈：Blockbench MCP プラグイン（jasonjgardner/blockbench-mcp-plugin）で GPT に操作させる、GPT が `.bbmodel` を直接読み書きする、OBJ を見せて 1:1 で組ませる（「模生模」）、公開スキル Srar-Git/minecraft-modeling-item（灰色の塊で輪郭→一部を完成→複製、斜面は回した箱、同じ条件で撮って比べる）。

ここから読める作り方：**本物の立体に箱を当てはめ、本物のテクスチャを箱の面に焼く**。丸い所（頭・爪・脚）は薄い輪切りと小さい箱の階段、平たい所（翼）は回した長い板。

分からなかったこと：作者が MCP を使ったか直接書かせたか、指示文、直した回数。作り方の動画は作者のチャンネル（全 6 本）に無い。

### 動きがなめらかな理由（30fps でコマ送りして確かめた）

- 止まるコマが無い。どのコマも前のコマから少しだけ動く（キーの間が曲線でつながっている）。
- 予備動作と余韻：なぎ払いは、翼を真上に上げる（約 0.2 秒で振り下ろす）→ 体ごと回る → 終わりの 0.6 秒ほどはほとんど動かずに収まる。
- 遅れてついてくる部分：尾は付け根から先へ順に曲がり、翼は腕（肩・ひじ・手首）と刃の束が別々に動く。尾と首が何節もある。

## 物差し

| 項目 | 手本（動画） | 雑魚モブ（PR #238） | この習作 |
|---|---|---|---|
| 箱の数 | 約 500（コメント）。爪・頭は 1px 級の箱 | 33〜87 | 2346（うち回した箱 2023） |
| 骨 | 不明（尾・首・翼の腕が多節） | 6〜9 | 37（尾 6・首 3・翼は片側 6） |
| テクスチャ | 立体から焼いた連続した絵 | 箱ごとに 3〜4 色 | 2048px、1px あたり 3 テクセル、立体の位置から焼く |
| 輪郭 | 低い体、太い首が頭へ下る、背に反った厚い刃 3 本×2 | 人型の箱 | 同じ構成（刃は反り 20°） |

雑魚モブとの違いを一行で：あちらは「箱を置いて箱ごとに塗る」、手本は「立体に箱を当てて立体の絵を焼く」。

## 作り方（手本の手順を、自前の立体でなぞる）

1. **立体**：体を、先細りの丸い棒をなめらかにつないだかたまりとして書く（`solid()`、`PRIMS`）。
2. **輪切り**：部位ごとに軸へ直角に薄く切り、1 枚を数本の帯に分け、帯ごとに立体の幅の箱を 1 個置く（`slices()`）。
3. **刃・棘・爪**：回した長い箱を線に沿って置く（`finger()`、`spike()`、`toe()`）。刃は反らせる（`ARCH`）。
4. **焼く**：色は箱ごとに塗らない。面の 1 テクセルごとに、立体の上のその場所の色を材質に聞く（`shade()`、`bake()`）。明るさ・鱗・装甲の継ぎ目・くぼみの暗さ・赤い皮が、箱をまたいで続く。
5. **動き**：姿勢を時間の関数で書き、0.05 秒ごとにキーへ焼く（`valstrax_anim.py`）。キーの間は曲線、技は「ため→一気→長い余韻」、尾は体の向きを節ごとに遅れて追い、首は先に向く。

アニメーション：`idle`（翼をたたんだ待機、4.0 秒）、`walk`（1.2 秒）、`turn`（振り向き 90°、2.6 秒）、`wing_sweep`（翼の刃でなぎ払い、2.6 秒）、`jet_stance`（翼を後ろへ上げて開く構え、3.2 秒）。

## 比べた結果

手本の 3 コマ（たたんだ待機・翼を上げた姿・寄り）と同じ角度で描き、旧版と新版を並べて、まっさらな判定役 3 人に「どちらが手本に近いか」を聞いた（左右は入れ替え）。

| 周 | 変えたこと | 新版を選んだ人数 | 扱い |
|---|---|---|---|
| 1 | 式で箱を並べる版（1256 個）。藍が見て「もう違う」 | 判定に出していない | 捨てた。作り方を「立体→輪切り→焼く」に替えた |
| 2 | 刃を太く・反らせる（9°→20°）、構えの翼を高く | 2 / 3 | 残した |
| 3 | 胸を高く、頭を短く厚く、刃を広く、銀を明るく、赤を筋に | 1 / 3 | 上がったとは言えない |

判定役 6 人とも「手本と同じ品質ではない」「厳しい人は微妙と言う」。点は 5 点満点で、輪郭 2〜3、翼 2〜3、体と頭 2、質感と色 2〜3、細部の密度 3。

判定の弱み：2 周とも 6 人全員が下の段（B）を選んだ。並びに引っ張られていて、新旧の差（判定役も「僅差」と書いた）を測れていない。
3 周目は決まりどおりなら戻す所だが、2 周目の版を別に保存していなかったので、ファイルは 3 周目のまま。ここは手順の失敗。

## 届かなかった所

判定役 6 人がそろって挙げた順。

1. **翼**：手本は厚く幅広い刃が段になって重なり、背の上にかぶさる塊。こちらは平行な細い筋の並びに見える（「櫛」「羽の束」）。
2. **体と頭**：手本は胸が厚く、首が弓なりで、頭は短い楔に角が流れる。こちらは低く這うワニ型で、背が煉瓦の階段。
3. **質感**：手本は銀に濃淡と汚れがあり、暗い赤がにじむ。こちらは平らな青灰に赤の四角が乗って見える。

根の理由は二つ。手本は本物の立体と本物のテクスチャを写している。こちらの立体は丸い棒をつないだだけで、装甲の板・筋肉・顔の起伏が無い。
同じ品質に届くには、立体そのもの（彫った形）の質を上げるしかない。箱への写し方と焼き方は、この手順で足りる。

## 確かめていないこと

- Blockbench の実物で開いていない（この PC に入っていない）。`boss_models.validate_model` は通る。絵は `valstrax_view.py` の計算で描いたもの。
- ゲームの中（WSEE）で出していない。箱 2346 個・8MB は黒翳竜（1132 個）の倍で、重さは未計測。
- 回転の向き：ほかのボスのスクリプトと同じく x だけ符号を反転して書いた。Blockbench の画面で左右が逆に見える可能性がある。

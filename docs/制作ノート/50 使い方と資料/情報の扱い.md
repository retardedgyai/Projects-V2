# 情報の扱い

## 何を作るか

次の順番で信用する。

1. 自分で確認し「仕様確定」にした個別仕様
2. 自分が記録した判断
3. ゲーム全体の方向や共通ルール
4. 「要確認」の取り込み候補
5. 昔のアイデア、調査、予定表

正式仕様同士が食い違ったら、AIが新しい方を勝手に選ばず、自分が決め直す。

## 今何が動くか

次の順番で確認する。

1. 基準ブランチへ入ったコードとテスト
2. 現在作業中のコードとテスト
3. 実装状況の記録
4. 昔の予定表や実装メモ

## 今回どこまで作るか

GitHubの課題に書く。ただし、ゲーム仕様はコピーせず、Obsidianの仕様ページへリンクする。

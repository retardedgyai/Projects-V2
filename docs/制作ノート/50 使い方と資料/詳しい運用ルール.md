# 詳しい運用ルール

このページはAIや開発担当も読むためのもの。普段は読まなくてもよい。

## Obsidianの役割

- `docs` フォルダがProjectSの外部脳。
- 別の保管場所へ同じ仕様をコピーしない。
- 自分で確認した「仕様確定」のページだけが正式仕様。
- AIが整理しただけのページは「要確認」。
- GitHubの課題には、仕様をコピーせず仕様ページへのリンクを書く。
- コードは「今どこまで動くか」の証拠であり、ゲーム仕様を勝手に変更しない。

## 思いつきから完成まで

1. 思いつきを雑にメモする。
2. 必要ならChatGPTと一緒に内容を詰める。
3. 自分で選ぶ必要がある部分を分ける。
4. 完成した仕様を自分で全部読む。
5. 納得したら「仕様確定」にする。
6. 仕様を参照して実装課題を作る。
7. ゲーム内で実際に触る。
8. 感覚が違ったら、理由を残して仕様を直す。

## ページを分ける基準

- 「戦闘」「属性」「ボス」のような大きなページは全体の案内図にする。
- 実際に完成を判断する仕様は「炎」「氷」「特定のボス」のように分ける。
- 1ページを読めば、その内容を頭の中へ戻せる状態にする。
- 必要になる前に空のページを大量に作らない。

## 情報を混ぜない

- 何を作るか: 本人確認済みの仕様ページ
- 今何が動くか: コードとテスト
- 今回どこまで作るか: GitHubの課題

矛盾したらAIが勝手に直さず、自分が決めることとして戻す。

## 同時にやりすぎない

- 今作る大きなものは原則1つ。
- 未決定の内容をAIに勝手に決めさせない。
- 必要になる前に大きな共通システムを作らない。
- ブランチ名やコミット数など、すぐ古くなる情報を正式仕様へ書かない。
- `main`へ直接pushしない。

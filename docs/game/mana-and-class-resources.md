# マナ / Cooldown / 固有ゲージ設計

## 基本原則

ProjectSでは、全Playerが共通の「マナ」を持つ。

ただし、全クラスが同じ重さでマナ管理を要求されるわけではない。

### マナ

役割:
- Skillを使うための共通燃料。
- 長期的にどれだけSkillを回せるかを制御する。
- 最大マナ、回復、消費軽減などをBuild要素にできる。

初期原則:
- Skill 1〜3は原則マナを消費。
- 通常攻撃はマナ不要。
- 回避はマナ不要。
- Ultは別条件/専用ゲージ等を後で決める。

### Cooldown

役割:
- 同じ技をどれくらいの頻度で使えるかを制御する。

マナとCooldownは別の役割を持つ。

例:
- 戦士: マナ消費小 + Cooldown長め。
- 普通のMage: マナ消費中〜大 + Cooldown中程度。
- 連射型Mage: マナ消費大 + Cooldown極短/ほぼ無し。

### 固有ゲージ

役割:
- そのクラスらしい戦い方を上手く行ったことへの報酬。
- マナの代替や二重制限として使わない。
- ゲージの「増やし方」はクラスのアイデンティとして基本固定する。
- ゲージを「何に変換するか」は装備/MOD/ビルドによってある程度変化してよい。

例:
- 戦士系: 前線で攻撃を当て続けることで「闘志」を溜める。
- 遊撃系: 攻撃・回避の流れを切らずに「勢い」を維持する。
- 魔術系: マナを使って魔法を回すことで「共鳴」を溜める。

## クラス固有ゲージの設計方針

ProjectSでは、固有ゲージをクラスのアイデンティとして扱う。

基本ルール:

1. **増やし方はクラス固有**
   - そのクラスらしい行動をすると自然に増える。
   - 例: 戦士は前線で戦い続ける、遊撃は攻撃と回避の流れを維持する、魔術はマナを使って魔法を回す。

2. **使い道はビルドで変えられる**
   - 同じクラスでも装備/MODによってゲージの変換先を変えてよい。
   - 例: 維持して常時強化、一定量を消費して大技強化、満タンで自動覚醒など。

3. **マナと同じ仕事をさせない**
   - マナはSkillを使う共通燃料。
   - 固有ゲージはクラスらしい戦い方への報酬。

4. **ゲージ不足で通常戦闘を止めない**
   - 固有ゲージが0でも通常攻撃・回避・基本Skillが原則機能する。
   - 固有ゲージは「できなくする」より「上手くやるとより強くなる」方向を優先する。

### 現在の3クラス案

#### 戦士系 — 闘志

狙い: 前線で戦闘を継続するほどエンジンが掛かる。

候補の増加条件:
- 攻撃命中。
- 強い攻撃の命中。
- 戦闘継続。
- 敵攻撃を上手く避けた場合の少量獲得。
- 被弾による獲得を入れる場合は、被弾推奨にならない程度に弱くする。

候補の使い道:
- 高闘志時にSkill強化。
- 一部Skillで闘志を消費して追加効果。
- MODによって「維持型」「消費型」「満タン覚醒型」へ分岐可能。

#### 遊撃系 — 勢い

狙い: 攻撃と回避の流れを切らず、動き続けるほど強い。

候補の増加条件:
- 連続命中。
- Skill命中。
- 回避成功。
- 一定時間攻撃成功がない場合は徐々に減衰。

候補の使い道:
- Skill性能や機動性の強化。
- マナ回収補助。
- MODによって維持型/消費型へ分岐可能。

穿龍棍・双剣・弓のどれでも成立することを前提にし、近接コンボ数だけには依存させない。

#### 魔術系 — 共鳴

狙い: マナを使い、魔法を回した結果として強化された魔法を作る。

候補の増加条件:
- マナ消費量。
- Skill命中。
- 特定の魔法順序/条件。

候補の使い道:
- 次のSkill強化。
- 一定量で特殊状態へ移行。
- MODによって「大量マナ消費で高速蓄積」「小刻みに何度も発動」「満タン覚醒」などへ分岐可能。

魔術系ではマナそのものが既に戦闘要素なので、共鳴は単なる第二の支払い資源にはしない。

## クラスごとのマナ重要度

### マナをほぼ考えなくてよいクラス

普通にSkillを回している限り、自然回復が消費へほぼ追いつく。

狙い:
- Playerに主にCooldownや固有ゲージを見せる。
- ただし特殊BuildやDebuffでマナが意味を持つ余地は残す。

### マナを多少考えるクラス

長時間Skillを連打すると枯れるが、通常戦闘では頻繁に停止しない。

狙い:
- 「今このSkillへ払うか」を判断させる。

### マナが戦闘の中心になるクラス

最大マナ、回復、消費軽減が直接Skill回転や瞬間火力へつながる。

例:
- 大容量マナを積み、短時間に一気に吐く。
- マナ回復を積み、長時間回し続ける。
- 消費軽減で効率を上げる。
- 命中時にマナを返して継続火力を維持する。
- マナを意図的に使い切ることで覚醒する。

## マナ回復

基本ルール:
- 戦闘中も自然回復する。
- 戦闘外では高速回復する。
- クラス、Skill、装備、MODによって追加の回復手段を持ってよい。

マナ切れで長時間何もできない状態は避ける。通常攻撃と回避は常に使える。

## マナ関連MODの考え方

マナ関連MODはクラス専用に分けず、共通MODとして存在してよい。

ただし価値はクラス/Buildによって大きく違ってよい。

候補:
- 最大マナ +X%。
- マナ回復 +X%。
- Skillマナ消費 -X%。
- 命中時に消費マナの一部を返還。
- 一定量のマナを消費するごとに次Skill強化。
- 現在マナが高いほどDamage増加。
- マナが低いほどDamage増加。
- Skillのマナ消費を増やす代わりに威力増加。
- 味方へマナを供給するSupport効果。

全MODが全Buildに有用である必要はない。

「自分には神MODだが別クラスには不要」という差をBuild個性として許容する。

## マナと固有ゲージを両方使う場合

悪い例:

`Skillを使うたびにマナ30 + 固有ゲージ40 + Cooldown12秒`

これを全Skillへ要求すると三重制限になり、操作の楽しさを削りやすい。

良い例:
- マナ: Skillを使う共通燃料。
- Cooldown: 個々のSkill頻度。
- 固有ゲージ: 上手い戦い方をした結果、強化状態/特殊技/追加効果へ変換。

固有ゲージを上手く使った結果としてマナが返る設計も許容する。

例:
- 連撃20Hitでマナ回復。
- 弱点Skill命中で消費マナ返還。
- 覚醒終了時にマナ回復。

これにより、マナ管理を「待つだけ」ではなく「上手く戦うことで解決する」にできる。

## 参考にする他ゲームの考え方

- League of Legends: マナは長期的なSkill連発の制限。装備でマナ問題を軽減/解決するBuild要素がある。
- Lost Ark: MPという共通資源の上にクラス固有ゲージを置き、固有ゲージはクラスの本当の遊び方を作る。
- FFXIV: 同じMPでも、黒魔道士のように「使い切る→回復する」の循環そのものをクラス設計にする例がある。
- ESO: 資源をCooldown代替のように扱い、通常攻撃で資源を回収する例がある。
- Guild Wars 2: 共有資源を使って同じSkillを連続使用できる設計がある。
- Path of Exile: マナ問題そのものをBuildで解く。

ProjectSではこれらをそのままコピーせず、クラスごとに「マナをどれだけ意識させるか」を設計軸にする。

# ProjectS v2 戦闘原則

この文書は戦闘の現在方針をまとめる。具体的な数値は初回プレイテストで変更してよい。

## 一人称を基準にする

ProjectSの戦闘は一人称を正式基準にする。Minecraft特有の没入感を残すため、攻撃の見え方、視覚エフェクト、Boss予兆、距離感は一人称で調整する。

三人称は使いたい人が使えてよいが、三人称専用の最適化は初期Scopeに入れない。

## 通常攻撃は武器ごとの基本行動

Vanilla Minecraftの近接攻撃ルールを全武器へ共通適用しない。

通常攻撃入力は「その武器の最も基本的な戦闘動作を行う」という意味にする。

例:
- 剣: 基本斬撃。
- 重い剣: 大きく重い斬撃。
- 穿龍棍系: 高速な近距離連撃。
- 槍: 細く長い突き。
- 弓: Minecraftの長押しで引いて離して撃つ感覚を活かす候補。
- 杖: 基本魔法弾など武器固有行動。

### 長押しと入力

近接通常攻撃は一旦「押している間、武器固有テンポで攻撃を継続する」を採用する。

ClientからServerへ通常攻撃の状態変化として送るのは原則 `押した / 離した` だけにする。保持中を毎tick送らない。Serverが「押し続けている状態」を記憶し、一撃が完了した時点で次の通常攻撃を開始する。

ClientはHit対象を申告しない。攻撃可能か、いつ次の一撃が始まるか、誰にHitしたかはServerが決める。

## 一撃の時間構造

初期Combat Spikeでは、最低限一撃を次の3段階で扱う。

1. **攻撃が出るまでの時間** — 入力から攻撃判定が出始めるまで。
2. **攻撃判定が出ている時間** — 実際に対象へ当たり得る時間。
3. **攻撃後の隙** — 判定終了後、次の通常攻撃・Skill・回避へ移れるまで。

「一撃が終わる」とは、攻撃後の隙まで完了した時点を指す。

通常攻撃の判定が出る前（1.の間）は回避でもSkillでも途中キャンセルしない。入力は予約され、判定が出た後に実行する。判定が出た後の隙（3.）は回避で切れる（2026-10-19、MH×MMOの見直し）。

これによりAttack Speedを上げるとDPSだけでなく次行動へ移れる頻度も上がる。この効果が強すぎないかはCombat Spikeで確認する。

## Attack Speed

Attack Speedを積んでも高速クリックを要求しない。Attack Speedは武器そのもののテンポを変える。

ただし全武器の全時間を単純に同じ倍率で短縮する必要はない。

初期方針:
- 重い剣: 攻撃そのものの重量感を残し、主に攻撃後の隙と次攻撃への移行を短縮する。
- 穿龍棍系: 攻撃が出るまで・攻撃判定・攻撃後の隙を含む全体テンポへ比較的強く反映する。
- 弓: 引き絞り/次射撃準備を短縮する候補。

Combat SpikeではBaseline / +50% / +100%程度をまず比較する。極端な値で複数の攻撃段階が同一Server tickへ潰れるような試験は避ける。

## 攻撃は空間に判定を出す

Vanilla melee hitを主判定にしない。

各攻撃は明示的な空間形状を持つ。
- 横薙ぎ: 扇/太い軌跡。
- 突き: 細い直線/カプセル。
- 近距離打撃: 小さい前方領域。
- 叩きつけ: 直撃+着地点の円。
- 突進: 移動する攻撃領域。
- 弓/魔法弾: Projectile。

視覚エフェクトとServer側の判定は可能な限り一致させる。

一回の攻撃で同じ対象へ意図せず複数Hitしない。多段技は明示的に複数Hitを定義する。

## PlayerとMobは同じ戦闘文法

Mobに触れた/近づいたこと自体では原則Damageを受けない。

Mobも必ず明示的な攻撃を行う。
- 爪
- 牙
- 拳
- 角
- 尻尾
- 武器
- 魔法
- 突進用の攻撃領域

PlayerがBossの至近距離にいても、その攻撃判定を避け続けられるなら攻撃し続けてよい。

大型Mobの身体は物理的にPlayerを押し出してよいが、身体衝突とDamageは別概念。

## ロックオンなし

ロックオン、自動敵向き補正、攻撃の磁石化は基本的に使わない。

攻撃はPlayerが見ている方向へ出す。必要ならMinecraft操作に合わせて攻撃形状を少し寛容にするが、自動命中にはしない。

## 回避

WASDで押している方向（無入力なら正面）+回避キー（F）でステップする。2026-10-19の見直し（藍「MH×MMO。突っ立ってたり欲張り過ぎたらすぐ食らう」）で、次の決まりにした。

- 2.6ブロックを4tickかけて滑る（押した瞬間に1歩目、瞬間移動ではない）。壁・段差の手前で止まる。
- **無敵時間あり**：押してから7tick（約0.35秒）は被弾しない。防御無視（TRUE）の大技（大詠唱・殻の失敗など）は回避でも抜けられない。
- 再使用1.2秒（ノードで1.0秒）。スタミナなし。
- **出し切り**：通常攻撃の判定が出る前と、重い技（溜め12tick以上）・奥義の溜め中は回避で切れない。そこで押した回避は8tick予約され、切れるようになった瞬間に出る。軽い技の溜めと、判定後の隙は回避で切れる。

## 動きながらの攻撃と被弾

- 歩きの速さ：近接の通常攻撃中は0.6倍、軽い技の溜め中は0.35倍、重い技・奥義の溜め中は止まる。
- **怯み**：防御なしで最大HPの20%以上を一度に受けると、技が消え、0.5秒操作できず、敵から2.5ブロック押し出される。
- **吹き飛び**：45%以上なら1秒倒れて4ブロック飛ばされる。倒れている間と起き上がり（+0.4秒）は無敵（はめ殺しにしない）。
- 防御（構え）で受けた攻撃と、障壁で吸った分は怯まない。継続ダメージも怯まない。

## 技選びの手応え

- 技の属性（火1・氷2・雷3）が敵の弱点と合えば、装備の属性と同じく×1.25で「弱点」表示。
- 黒翳竜は部位で通りが変わる：頭（正面50°以内、近接は頭の近く・射撃は正面から）×1.25で弱点表示と音、しっぽ側（後ろ40°以内）×0.8。
- どの職業にも崩しの技が1つある（戦士は既存、メイジ霜の波紋＝拘束、レンジャー貫き矢・アサシン断命・テンプラー裁きの槌・ヒーラー断罪の柱・星織り師星砕き＝怯み）。ボスには崩しゲージとして効き、大詠唱・殻の間は1回で最大HPの2%（怯み等の軽い崩しは0.8%）を止める量・殻へ入れる。

## Skill構成

初期構成は:
- 通常攻撃
- Skill 1
- Skill 2
- Skill 3
- Ult
- 回避

Skill数が少なすぎて単調だと実際に感じた場合だけ増やす。

Skillはクラス由来を基本とする。武器は通常攻撃、射程、攻撃範囲、基本テンポ、一撃の重さ等を担当する。

通常攻撃中にSkillを入力した場合も、初期仕様では現在の一撃終了後に実行する。

## マナ / Cooldown / 固有ゲージ

- 全Playerに共通のマナ概念を持たせる。
- Skill 1〜3は原則マナ消費。
- 通常攻撃と回避はマナ不要。
- 戦闘中もマナは自然回復する。
- 戦闘外ではより高速に回復する。
- クラス、Skill、装備、MOD等が追加のマナ回復方法を持ってよい。
- Cooldownは個々の技の使用頻度を決める。
- マナは長期的なSkill使用量/Skill燃料を決める。
- 固有ゲージはクラスらしく上手く戦った報酬にする。

クラスによってマナ重要度を大きく変えてよい。
- 戦士型: 普通に使えばほぼ枯れず、主にCooldownや固有ゲージを見る。
- Mage型: 最大マナ、回復、消費軽減がBuildの中心になり得る。
- 特殊Mage: Cooldownを極端に短くし、マナさえあれば連射できる設計も許容する。

マナと固有ゲージを同じSkillへ毎回二重課税するような設計は避ける。

固有ゲージは最初から万能な共通システムを作らない。最初は一つのクラスで「クラスらしい行動で溜める → 一つの使い道で消費/発動する」まで作り、実際に遊んでから他クラスや複数の使い道へ広げる。

## Serverが最終判定

Clientは入力直後に視覚エフェクト/音/カメラ反応を出してよい。

Serverが決める:
- 攻撃可能状態。
- 攻撃者/対象の位置。
- 攻撃判定との交差。
- 最終Damage。
- 弱点/部位Hit。
- Reward。

Clientの「当たった」という申告だけでDamageを入れない。

## 通信遅延

初期は高度な時間巻き戻しHit判定を実装しない。

Serverの現在状態でHit/回避を決め、高Pingによる多少の不利は許容する。

代わりに:
- Client入力反応を即時にする。
- Boss攻撃に十分な読みやすさを持たせる。
- 見た目より不自然に大きい攻撃判定を避ける。

実測で100〜150ms程度でも理不尽な被弾が多い場合のみ、後から軽い補正を検討する。

## 命中の重さ

Server/Worldを止める本物のHit Stopは使わない。

Client側で:
- 火花/接触Burst。
- Impact Sound。
- 小さいCamera反応。
- Damage Number。
- 重い攻撃だけ短い視覚強調。

を使う。

空振りと命中は明確に違う感触にする。

## 視覚エフェクト

手作業の攻撃Animationがなくても戦闘を成立させる。

攻撃は主に:
- 明確な斬撃/突き/衝撃の形。
- 音。
- 命中反応。
- 武器固有テンポ。

で表現する。

大量の粒子より形の可読性を優先する。Human-facing VFX Editorは作らない。

初日のCombat Spikeでは高品質Rendererや汎用VFX基盤を作らない。既存Particle、単純な線/弧、Sound等で十分とし、表示実装がCombat検証を止めないようにする。

## 目指す熟練曲線

初心者:
- Bossが動いたら大きく離れる。

慣れたPlayer:
- どの攻撃か判別して、その攻撃範囲だけ避ける。

上級者:
- 最小限のステップだけで攻撃を避け、Bossへの攻撃継続時間を最大化する。

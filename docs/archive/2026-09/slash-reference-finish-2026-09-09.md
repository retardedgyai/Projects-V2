## 開始時の判定と変更

開始時点は未達。形が動く点では進歩していたが、細い帯・同系色の明暗・平面的な接触光に寄り、参照の主役と脇役の強弱が不足していた。

| 不足 | 実装した変更 | 確認方法 |
|---|---|---|
| 切断面が細く、技の山場が弱い | 技ごとに内側の幅を広げ、細い縁・中間面・暗い内側・内部の光の筋を分ける | 全7技の実モデルを正面・斜めから時系列描画 |
| 単色の濃淡に見える | 面ごとに3色の独立したtintを割当。鋼青、琥珀、紫の中間色と縁の色相を変える | 315モデルの全faceとitem tintを検査。プレビューもface別tintに対応 |
| 輪郭と同じ平面の残光だけ | 刃先経路から時間差で7片が離れる。3枚の大きめの裂片＋4本の細い火花、面の表裏への移動と傾斜 | 座標・時間変化・消滅をテスト。別ItemDisplayは追加しない |
| 接触が平たい星型で終わる | 1回の圧縮光から、奥行きのある異なる5方向の破片へ遷移 | 空振り／命中例の比較。CONTACT以外に命中光を追加しない |
| 正面から裂傷斬り・地砕きが線に見える | 固定面角度を修正。PNG全体を回転する方式には戻さない | 主面の面積で重み付けした正面投影率を2コマで検査。下限を0.12から0.18へ強化 |

主面→残光→消滅の順序、加速する輪郭、正面での色面の読み分けは簡易描画上で改善を確認。短い斬り、逆薙ぎ、縦斬り、一周、交差、分節した短剣の輪を同じ形へ統一していない。

## 実装と検証

- 最重要：`scripts/build_greatsword_sweep.py`（色面、湾曲面、裂片、接触破片）。各技の経路は `scripts/build_expanded_slashes.py`。
- 割当・角度：`CoreExpandedSlashChoreography.kt`。既存の `CorePlayerCombat` → PREPARE/PULSE/CONTACT → choreography → ItemDisplay の経路を維持。
- 描画は固定位置・姿勢のItemDisplayに毎コマ異なるnativeモデルを渡す。厚い箱の寄せ集めでも、完成PNGを回す方式でもない。既存PNGから不透明の白1画素を色の供給に使い、輪郭はgeometryで定義。
- 新しい表示entity、描画レイヤー、共有Framework、音の追加はない。8tick間隔の既存多段判定、空振りと命中の区別を保持。
- 315モデル、最大244面片／モデル、モデルJSON合計2,372,613 bytes（非圧縮）。要素数増加はあるため、多人数の実機負荷を未検証のまま「負荷が変わらない」とはしない。
- Kotlin関連174件成功。Pythonは既存9件＋新規5件。新規検査は全630モデル/item定義の再生成一致も含む。
- Vanilla 26.2実CuboidModelパーサーで315件を検査。紫黒モデルの予防として資源参照と合法なnative回転を別々に確認。

## 判定の限界と次の確認

この確認はゲーム画面ではない。実際のGPU描画、明るい昼間の背景、他プレイヤーからの視認、通信、音、操作感は含まない。参照動画側のキャラクター動作・環境演出を、こちらの斬撃だけのプレビューと同等条件として比較していない。

したがって「参照と同等の総合品質に達した」という完成判定はまだ出さない。コード／パックで検出できた不足を仕上げたcheckpointであり、未確認の実機品質をテスト件数で代用しない。Creatorがゲーム操作・最終feelを判断するrepoルールに従い、今回ゲームは起動・操作していない。

再確認用：`.tools/slash-finish-eye.gif`。サーバーの実PREPARE/PULSE時間で全7技を描画し、連撃の判定数を動画編集で増やさない。命中を仮定しない全体版と、`.tools/finish-v5-contact-*.png` の命中／空振り例は分ける。

壊れたときは、形と色なら上記2生成スクリプト、方向なら `CoreExpandedSlashChoreography.kt`、紫黒なら `core-ui-pack/index.txt` と `items/models/combat_vfx/` の対応を最初に見る。
`.tools/` と `.kotlin/` はcommitしない。mainに変更せず実験branchへ通常pushする。

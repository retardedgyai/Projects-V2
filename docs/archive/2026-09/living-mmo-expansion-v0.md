# 生活職と星環の深殿 v0 — 実装契約

2026-09-06 / `play/gyai/living-mmo-expansion`。現行の装備・強化破損・修理・UIを土台にする。
今回の大型実装に必要な情報は専用 core-loop 保存へ追加し、旧データはバックアップして移行する。
Protocol、クライアント、汎用Particle Frameworkの境界は変更しない。mainへの採用は別レビュー。

## プレイヤーの選択

- 採取者：既存の採取技能と密集地域を活用。採取の実績から上位地図へ進める。戦闘討伐を生活職の必須条件にしない。
- 精製・製造者：購入原料でも専門経験を得る。まとめて生産し、素材の節約と製作品質を育て、装備ベースや修理用装備を売る。
- 戦闘者：オーブと銀貨の元を集め、プレイヤー製のベースを買ってMOD厳選・強化する。戦闘から採取原料を直接供給しない。
- 仲間と遊ぶ人：港で募集・参加し、1〜4人の専用ダンジョンを攻略。ソロでも全ギミックを解ける。

安定職は「損失リスクが低い」という意味で、売却利益を無条件に保証しない。NPC無限買取、必須デイリー、PvP損失は追加しない。

## 星環の深殿

部屋形状・テーマ・分岐・遭遇・加護をseedから組み合わせる。周回限定の加護は永久装備と分離する。
数値だけ増やす難度ではなく、上位挑戦では機構の重なりや追加対処を増やす。
ボス戦は予兆→対処→攻撃機会。フェーズ飛ばし、全滅、退出、切断、二重報酬、消し忘れを自動検証する。

参考：Monumenta公式の `DepthsParty` / `DepthsRoomChoiceGUI` を2026-09-06に確認。
部屋の選択、周回状態、報酬を分ける関係を参考とし、コード・世界・専用アセットは移植しない。
https://github.com/TeamMonumenta/monumenta-plugins-public/tree/master/plugins/paper/src/main/java/com/playmonumenta/plugins/depths

## 受け入れ条件

1. 港の既存メニューから生産成長・注文取引・深殿へ実際につながる。
2. UIが示す費用・不足・効果と、サーバーの確定処理が同じ定義を使う。
3. 調整値を独立した設定に置き、無効値は起動時に拒否する。
4. 保存失敗・同時売買・再送で物品や銀貨が増減しない。旧装備のMOD、強化、識別番号を保持する。
5. 100時間級を目標とするが、組合せ数や反復回数を実測プレイ時間と呼ばない。面白さと難度はCreatorの手動評価が必要。

## 実装した遊びの流れ

採取遠征 → 密集地域を探す → 原料を持ち帰る → 精製 / 製造 → 市場・購入注文へ供給。
戦闘遠征 / 深殿 → オーブ・戦利品券 → 換金 / 原料・装備購入 → MOD厳選 / 強化 → 次の挑戦。
強化で破損した装備には、既存仕様どおり同Tier・同系統の未破損+0装備を使って修理する。
通常の戦闘だけで装備を摩耗させる仕組みや、死亡時の全損は追加していない。

### 採取と生産

- 採取済みオブジェクトごとに `地図Tier` 分の調査実績。採取量MODで実績が水増しされることはない。
- 調査実績40 / 240 / 900でT2 / T3 / T4の採取地図を作れる。上位地図の代価は一つ下のTierの原料4個。T1は無料。
- 採取だけでも地図Tierを解放できる。通常遠征の敵は残るが、討伐・ボス攻略は解放の必須条件ではない。
- 精製5職（木工 / 鉱石 / 石材 / 皮革 / 繊維）と製造2職（武器 / 防具）が別々にLv0〜100へ成長。
- 精製は原料2→精製品1を維持。熟練による原料還元は最大20%。端数を保存し、クリック分割で端数を稼げない。
- 製造は1〜16個のまとめ生産に対応。製造品質0〜20%は武器の基礎攻撃・防具の基礎HPに反映。
- 製造熟練は品質の最低値と複数回抽選の良い方を採用する回数に作用する。品質とMODのレア度・ロール品質は別物。
- 品質が低い装備も修理材料として使用可能。既存装備の製造品質は0%として移行し、既存能力を下げない。

### 生産品の買い手を見つける

購入注文は「売ってから買い手を待つ」出品の逆向き。買い手が銀貨を預け、必要な原料 / 精製品 / 修理用装備を指定する。

- 素材は種類・Tier・数量・単価、装備は系統・Tier・数量・単価で指定。
- 売り手は一部納入できる。装備は対象の個体を選んで確認してから渡す。装備中・帰属済み・破損・強化済みは納入不可。
- MODや製造品質が高い+0装備も条件に合えば納入可能なため、確認画面に個体と消失する内容を表示する。
- 売り手手数料5%（切上げ）、注文取消は未充足分だけ返金。買い手がオフラインでも納入可能。
- 既存の2者間ジャーナルで銀貨と物品を一括確定。並行納入・再送・中断後復旧を検証。
- 注文は実在するプレイヤーの資金で成立する。利益、買い手の存在、常時成約は保証しない。

## 星環の深殿 — 今回の範囲

港の「冒険の手帳 → 深殿」から、一人で出発 / 募集 / 参加。
募集は最大4人、全員が準備完了後にリーダーが出発する。途中参加や切断後の再入場はまだない。
同じインスタンス・同じ敵を共有し、部屋の戦利品は各参加者へ個別に確定する。奪い合いの床ドロップではない。

- 標準3層・進行12部屋。各通常段階は2択、各層の最後は必須ボス。生成する実体は選ばない分岐を含め21室。
- テーマ3種：灰燼の工廟、蒼潮の書庫、星蝕の王庭。
- 建築構成6種：八角、回廊、宝物庫、書廊、庭園、坩堝。戦闘コアは平坦で装飾を置かず、外周の柱・壁・照明・床模様を組み合わせる。
- 内容6種：守衛、精鋭、宝庫、封印、憩い、守護者。通常2波、宝庫3波、封印は戦闘と3地点の解読、憩いは回復。
- **部屋間は祭壇で進路を選ぶ転移型**。連続した洞窟・廊下を自由移動する迷路生成ではない。組合せ・配置・遭遇の手続き生成であり、手作業でマップを制作する方式ではない。
- 部屋クリア後、各自3択から加護を選び、全員の選択後にリーダーが次の部屋を決める。精鋭・ボスの加護は2段階分。
- 加護12種：剛力、疾風、戦技、生命、循環、集中、守護、軽歩、熾火、霜花、雷光、狩眼。装備データは書き換えず、帰還で消える。
- 深度0〜20。Tierごとに一つ前の深度を踏破すると次を解放。深度4以降は精鋭増援、8以降は星落とし拡大、12以降は複合予兆。
- 共有復活2回。味方の倒れた位置を右クリックし3秒近くで救助。全滅は6秒後、復活を1回使って同じ部屋を再挑戦。
- 復活が尽きても獲得済み報酬は保持。部屋突破時には倒れていた仲間を復帰させる。
- 個別帰還・切断で残った仲間の世界を閉じない。リーダー不在時は残った先頭のメンバーへ移る。
- 保存が未完了なら次の部屋へ進めない。転送の完了前に戦闘を開始しない。最後の参加者が離れた世界と表示Entityを回収する。

### 新ボス3体

各ボスはHP70 / 40 / 15%で必ず障壁フェーズへ入る。高火力でも飛ばせず、解除後3秒間の攻撃機会を作って次の形態へ進む。

| ボス | 機構・フェーズの特徴 |
| --- | --- |
| 熔星の番人 | 3機構の停止、後半は盾兵・術師を同時処理。直線 / 回転した十字予兆を避けながら解除 |
| 蒼潮の記録者 | 表示された順序で碑文を起動。中盤は中央 / 外周の安全地帯が交互に変化。高深度では直線予兆も重なる |
| 星蝕の王 | 各プレイヤー位置への星落としから退避し、小さな安全円へ集合。最終障壁は星核の停止と護衛処理を並行 |

予兆は既存の赤い半透明の床表示。サーバー判定の形と表示が同じ定義を使い、表示できなければその攻撃ではダメージを出さない。
制限時間を超えると追加の暴走予兆が出るが、見えない即死・人数固定の失敗条件にはしない。すべてソロで解除可能。

### 深殿の報酬

- 部屋：同Tierの戦利品券3枚 + 深度補正、通常は改変1個、宝庫は混沌1個。
- 層ボス：混沌2個と高揚1個。
- 最終踏破：神聖1個 + 深度補正、**星環のオーブ1個 + 深度補正**、次の深度の解放。
- 星環のオーブ：レア装備のランダムなMODを一つ取り除き、一つ抽選して付け直す。他のMOD・強化・製造品質は保持。必ず良くなるものではない。
- 星環のオーブは深殿踏破限定。一般モブ・既存寄り道の抽選には入れない。
- 採取原料は報酬に含めない。戦利品券の換金から採取者・製造者の市場へ需要をつなぐ。

## 数値を後から調整する場所

標準値は `server-minestom/src/main/resources/core-mmo-balance.properties`。
上書きはサーバー作業ディレクトリの `config/projects/mmo-balance.properties` に必要な項目だけ書いて再起動。
Gradleの `:server-minestom:run` なら `server-minestom/run/config/projects/mmo-balance.properties`。起動中のホットリロードではない。

調整項目：生産経験曲線、精製/製造XP、原料還元上限、品質上限、採取Tier解放値、地図コスト、層数、部屋数、最大深度、人数/深度HP補正、ダメージ補正、券/ボス報酬数、復活回数、機構制限時間。
不明キー・型不正・範囲外は起動時に拒否する。無効な値を黙って採用しない。
加護の個別能力は `DungeonBoon`、ボス通常技は `QuestMobContent`、機構の形・HP閾値は `DungeonBossMechanics` に集約。
すべてを設定ファイル化した汎用コンテンツエディタではなく、今回の遊びを直接調整できる構成。

## 保存と運用上の限界

- core-loop schema v7。v1〜v6を読み、最初の書込み前に元ファイルを世代名付きで正確に保存する。MOD・強化値・破損・帰属・出品中の個体IDを維持。
- 操作レシートは最新4096件を保持。古いrevisionでの再送は拒否。完了runの個々の採取/戦闘ソースは整理し、開始済みrun番号は保持。
- run開始履歴は現行保存形式の上限16384件が残る。無期限の大規模運営には保存基盤・履歴保持方針の別設計が必要。
- 途中の部屋・加護・敵の状態はメモリ上。サーバー再起動後は港へ復旧し、**確定済み報酬は保持するが途中再開はできない**。
- 保存前にプロセスが強制終了した部屋報酬の復元は保証しない。通常の保存失敗はキューが再試行し、完了まで進行を止める。
- 今回のパーティ対応は新しい深殿のみ。既存のランダム採取遠征と欠片試練はソロのまま。
- 職業・ビルド・敵の種類は今後も必要。クラス追加、ギルド、住宅、チャット拡張、連続オープンワールド、大人数負荷試験は今回の実装には含まれない。
- 深度や組合せの反復量を「100時間の新規手作りコンテンツ」とは呼ばない。100時間飽きないこと、経済人口や相場、最適な攻略時間は未実測。

手動では次の3点を先に判断する。

1. 手帳→深殿→一人で出発。3択加護・進路決定・各ボスの赤い予兆が説明なしでも読めるか。
2. 二人以上で募集→準備完了→出発。救助と役割分担が楽しいか、途中帰還で残った側が遊び続けられるか。
3. 採取→精製→まとめ製造→購入注文への納入。得たオーブと強化・修理の消費が素材の売買へつながるか。

主な変更入口は `CoreDungeonExpeditions`（募集・生成・転送・帰還）と `DungeonRun`（一周の進行）。
問題が出たらサーバーログの `CORE_DUNGEON_STARTED` / `CORE_DUNGEON_BUILD_ABORT` / `CORE_DUNGEON_RUNTIME_FAILURE` とrun番号を最初に確認する。
保存の再試行が続く場合は `config/projects/core-loop` の書込み権限と保存ログを確認し、ファイルを消して解決しない。

この作業ではMinecraftを操作・再起動していない。自動テストとUIプレビューは実クライアントでのfeel確認の代わりではない。

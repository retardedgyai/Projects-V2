# Minecraft 26.3 への移行（2026-10-18）

サーバーは Minecraft Java 26.3（protocol 777、リソースパック形式 97.1）で動く。Minestom の 26.3 版は
まだ公開されていないので、作業中の PR を固定して使っている。

## 使っている Minestom

- PR: https://github.com/Minestom/Minestom/pull/3369（ブランチ `26_3`、head `b7c32f3bfa079e426ce817ec41a7fca0e625e48a`）
- 依存: `net.minestom:minestom:26_3-20261007.224755-10`（Sonatype の snapshot リポジトリ、`gradle.properties`）
- jar の中の `net.minestom.server.Git#commit()` は `d23134e8bd7d7ba70fe718d84fc2111e342cf691`
  （PR の merge commit `refs/pull/3369/merge`）。jar の sha256 は
  `7331c56f55eaf0cca234fd9c053eee3e73bf424a0aa79fe8d4f409c3cd94b9a4`。
- 時刻付きの版を指定しているので、PR が更新されても勝手に変わらない。

### snapshot が消えたとき

Sonatype は古い snapshot を消す。消えていたら同じ commit をローカルでビルドする。

```bash
git clone https://github.com/Minestom/Minestom.git && cd Minestom
git fetch origin pull/3369/merge && git checkout d23134e8bd7d7ba70fe718d84fc2111e342cf691
./gradlew publishToMavenLocal --max-workers=1
```

そのあと `build.gradle.kts` の repositories に `mavenLocal()` を足し、`minestom_version` を
ローカルに出た版（`26_3-SNAPSHOT`）にする。正式版が出たらそちらへ移る。

## 26.3 で直したところ

- 左クリックは `ClientAnimationPacket` から `ClientPunchPacket` になり、手の情報が無い。
  `PlayerHandAnimationEvent.hand` は常に `MAIN`。武器攻撃はもともと MAIN だけを見ていたのでそのまま動く。
  PR の説明では PunchPacket は左クリックだけで出る（右クリックの腕振りでは出ない）。実機ではまだ見ていない。
  web-ui-lab の左クリック検出は `ClientPunchPacket` を見る。
- `EntityAnimationPacket.Animation.SWING_MAIN_ARM` は消えた。採集の腕振りは `player.swingMainHand()`。
- `Block.isAir / isSolid / isLiquid` は `air() / solid() / liquid()` になった（`ItemStack.isAir` は変わらない）。
- `Block.blocksMotion()` は消えた。`BlockTags.BLOCKS_MOTION` で判定する（`VerdantRoadQuestDecorator`）。
- `ClientTeleportConfirmPacket` はクライアントの位置も持つ（テストだけ修正）。
- リソースパック形式 88 → 97.1（`scripts/build_*`、`verify_core_ui_assets.py`、polish05 の pack.mcmeta）。
- `scripts/shaders/item.{vsh,fsh}` は 26.3 の vanilla core/item を土台に作り直した。`#moj_import` → `#include`、
  入出力すべてに `layout(location = …)`（自作分は 7 = rawColor、8 = vfxPosition）。26.3 の半透明（OIT）は
  同じシェーダーを `OIT_ALPHA_ONLY` などの定義を変えて何度も通すので、VFX の分岐も最後は `finishUnlit` で
  vanilla と同じ OIT の処理を通る。

## WSEE（net.worldseed.multipart 13.0.4）

26.2 向けのビルドのまま使う。jar が参照する Minestom の API 190 個がすべて 26.3 の jar にあり、
94 クラスがリンクでき、未実装の abstract メソッドも無いことをリフレクションで確かめた。

ただし 1 か所、動きが変わって壊れていた。26.3 の `getEquipmentsPacket()` は装備が空だと `null` を返す。
WSEE の根本骨（armor stand）は新しい viewer にそれをそのまま送り、接続のキューが `null` で例外を投げて
モデルが出なくなる（`ShadeWyrmBossTest` が検出）。`BossModelView` の `generateRoot()` を上書きして、
空のとき AIR の装備パケットを返す根本骨に差し替えた。WSEE の座席骨（`ModelBoneSeat`）も同じ形だが、
今のモデルでは使っていない。

動き（移動補間など）はゲーム内で見るまで分からない。

## 確かめていないこと

- ゲーム内での攻撃・スキル入力、黒翳竜の表示と VFX の見た目（クライアントを起動していない）。
- Mojang はコアシェーダーの差し替えを公式には対応していない。コンパイルは NVIDIA のドライバで
  vanilla と同じ 64 通りの定義すべて通ったが、描画結果は実機で見る必要がある。
- パック内のモデル・フォントなどが 26.3 のクライアントで全部読めるか。
